1 整体概述

1.1 背景与目标

现状：开户时，销售、授信额度、返点、客情比例、联系人这些都靠手工在账户上填，跟客户登记表、规则配置、费用管理各记一份，容易对不上。v2.1.0 起客户信息从在线登记表来，返点和客情走规则配置，额度走费用管理。

目标：

  • 添加账户必须选一张该客户「待开户」的登记表；选中后投放类型自动带出；添加成功后，这张登记表自动变成「已开户」，并在 01 列表上显示绑定的账户。
  • 账户上不再手填那 11 个字段：其中 5 个由系统生成，销售改为跟随客户，其余的老值保留但不再展示。
  • 编辑账户只留真正需要维护的字段。

1.2 本页范围

  • ✅ 包含：
  • 添加账户页：字段调整、所属客户 → 登记表级联、投放类型回填、提交校验与 guard、系统生成字段、触发登记表「待开户 → 已开户」。
  • 编辑账户信息弹窗：字段调整、只读项、投放类型可改。
  • 登记表预览：编辑弹窗和账户列表的文件 icon 共用一套（D-02-06）。
  • 账户「销售」的取值来源（D-02-03），以及销售对账户的数据权限（R-02-027）。
  • 已禁用用户在优化师 / 合作者 / 观察者上的显示与保留（R-02-028）。
  • 账户「优化师」变更记录（R-02-026，供 11 按业务日取值，无展示界面）。
  • 下线旧「账户金额」接口及其导出（D-02-16）。
  • ❌ 不包含：
  • 账户管理列表的其他部分、授权弹窗（客户销售的只读显示除外，R-02-027④）、账户内部页：没改，沿用。
  • 登记表实体和状态机（归 01）；客户实体、客户状态机、客户的销售字段（归 04，本页只引用）。
  • 被删字段老值的迁移或清空：保留不动（D-02-02）；还在读老值的下游改从新来源取（R-02-015，技术已核实）。
  • 解绑或更换账户的登记表：本期没有（D-01-16）。
  • 编辑账户走审批：不走（D-02-01）。
  • 更换账户的所属客户、账户系统：本期不能改（R-02-017）；技术后台改数据按数据修复处理。

2.1.3 业务规则

  • R-02-001 账户管理列表点「添加账户」打开添加账户页（独立页面，面包屑「账户管理/添加账户」，底部按钮 返回 / 添加）。点「返回」回到账户管理列表，不保存已填内容。
  • R-02-002 字段按顺序为：账户系统、所属客户、登记表、账户选择、产品分类、投放类型、优化师*、合作者、观察者；下拉都可搜索。以下字段不再展示：销售、授信额度、苹果返点、客户返点、新品截止日期、客情比例、公司/产品名称、订单号、主要联系人姓名、主要联系人邮箱、结算联系人邮箱（账户管理.html:9846）。
  • R-02-003 账户系统默认填当前正在操作的账户系统。「账户选择」的可选账户在打开页面时和切换账户系统时重新查询，可选范围沿用现有实现（账户管理.html:9822）。在本页切换账户系统只在本页生效（D-02-10）：重新查询「账户选择」并清空已选账户；按 R-02-004 重新加载所属客户下拉，已选客户仍在新范围内就保留（登记表、投放类型随之保留），不在就清空所属客户和登记表、投放类型回到未选；产品分类、优化师、合作者、观察者保留。不改变全局账户系统；点「返回」回到列表时全局账户系统仍是进入前的那个。只有添加成功后才按 R-02-013 切换。
  • R-02-004 所属客户下拉的可选范围（D-02-09）：客户的账户系统等于本页所选账户系统，或客户还没有账户系统（新客户）。客户的账户系统取自它名下第一个账户：该客户第一个账户添加成功时写入（R-02-011 第⑥步），之后不再变。不受客户数据范围限制：有添加账户权限的用户（sys 与非 sys 一样）都列出全部满足上述账户系统条件的客户（D-00-77 例外；添加账户通常由优化师操作，2026-10-21 用户确认维持现状）。新建客户审批中的客户不在可选项里（R-04-006）。选项只显示客户名称，不带图标（现状里表示「客户尚未绑定账户系统」的「无用户」图标去掉）。切换所属客户时，清空已选的登记表，投放类型回到未选。
  • R-02-005 登记表和所属客户级联。没选所属客户时，登记表下拉禁用，占位提示「请先选择所属客户」。选了客户后，只列同时满足三个条件的登记表：关联客户 = 所选客户、状态 = 待开户、还没绑定账户；不限创建人（D-02-04）。选项显示「登记表名称（登记表ID）」（01 允许重名，靠 ID 区分），可以按名称或 ID 搜索。
  • R-02-006 所选客户名下没有符合 R-02-005 的登记表时，下拉展开显示「该客户暂无待开户的登记表」，没有可选项。登记表是必填，所以这种情况下添加不了。
  • R-02-007 投放类型：没选登记表时，两个选项都不选中。选中登记表后，自动选中这张登记表的投放类型（代投 / 自投），用户可以手动改（D-02-01）。换选另一张登记表时，按新登记表重新回填，覆盖手动改过的值。
  • R-02-008 点「添加」先校验必填（账户系统、所属客户、登记表、账户选择、产品分类、投放类型、优化师）。有缺失时，在对应字段下提示「请选择{字段名}」，不弹二次确认。
  • R-02-009 校验通过后二次确认「请确认信息是否正确？」（取消 / 确认）。点确认才提交；请求处理中，「添加」按钮显示加载，不能再点（账户管理.html:9822、9830）。
  • R-02-010 提交 guard，也就是 01 登记表「待开户 → 已开户」的前置条件，按服务端最新数据判断：所选登记表状态仍是待开户、还没绑定任何账户、关联客户等于所选的所属客户。任一条不满足：不创建账户，登记表不变，提示「该登记表已被使用或状态已变化，请重新选择」，清空已选登记表并重新加载登记表下拉。服务端另校验（防止绕过页面直接调接口）：所属客户必填；所属客户的账户系统等于本次账户系统或为空（R-02-004；不按客户数据范围校验）。不满足时不创建账户，提示「所属客户与账户系统不匹配，请重新选择」，清空所属客户、登记表并重新加载所属客户下拉。
  • R-02-011 guard 通过后，下面八步同成同败：①创建账户（页面所填字段）；②写入系统生成字段（R-02-012）；③登记表状态 待开户 → 已开户；④在登记表上写入所属账户系统（account_system）、绑定账户ID（account_id）；⑤所属客户为待开户时，客户状态 待开户 → 待投放（流转与规则由 04 定义，见 R-04-007；客户已是其他状态则不变）；⑥所属客户还没有账户系统时，写入本次账户系统（R-02-004）；⑦记录优化师初始值（R-02-026）；⑧按所属客户当前销售授予该账户的数据权限（R-02-027）。任一步失败，八步都不生效，提示「操作失败」，页面保留已填内容。
  • R-02-012 系统生成字段（前端不展示、不能改）：公司/产品名称 = 所选登记表「投放产品」的应用名称；订单号 = 「hby」+ 投放产品的应用ID（如应用ID 1234567890 → hby1234567890）；主要联系人姓名 = hby；主要联系人邮箱 = asa@hbyaso.com；结算联系人邮箱 = asabill@hbyaso.com。只在添加时写一次，之后改登记表不同步（D-01-06）。订单号不要求唯一（D-02-13）：同一投放产品开多个账户时订单号相同，允许重复；订单号用作广告系列预算订单的默认值、08 苹果订单按订单号归集到账户（一个订单号对应多个账户时按消耗拆分，08 定义），都不依赖唯一。其余 4 个字段（公司/产品名称与 3 个联系人字段）存发票信息表（invoice），用途是新建 / 编辑广告系列时作为苹果 LOC 发票信息的默认值，沿用现有（Q-02-03 已关闭）。
  • R-02-013 添加成功后弱提醒「操作成功」。如果新账户的账户系统和当前不同，先切换过去，再跳进这个账户内部（账户管理.html:9822 第 3.5.3 条）。

2.4 账户「销售」的取值与数据权限

2.4.1 功能描述

销售从账户上删掉了，但账户列表的销售列、高级筛选的销售、审批「绑定的销售」、销售的账户数据权限都还要用。v2.1.0 起账户列表与筛选里的销售实时跟随所属客户（D-02-03），提成按业务日的历史归属（D-00-72）；销售对账户的数据权限按 R-02-027 同步。

2.4.3 业务规则

  • R-02-015 账户不再维护「销售」：添加页、编辑弹窗都不展示。账户列表的销售列、高级筛选的销售、导出里的销售实时取账户所属客户的销售（D-02-03）；客户换了销售，这些地方跟着变。提成统计不实时取，按业务日的历史归属（R-11-003、D-00-72）。审批「绑定的销售」解析客户的销售（R-12-016），销售对账户的数据权限按 R-02-027。账户上的旧销售值保留不用（D-02-02），上述地方都不再读它。客户上的销售字段由 04 定义（R-04-004，原「商务」就是这个字段）。
  • R-02-027 销售对账户的数据权限（D-02-08）：①添加账户成功时，按所属客户当前销售授予该账户的数据权限（R-02-011 第⑧步；客户没有销售时不授予）。②客户销售变更生效时（04 直接保存成功、或客户信息变更审批通过，时点同 R-04-064），给新销售授予该客户名下全部账户的数据权限，同时收回旧销售因「客户销售」身份获得的授权；旧销售同时是某账户的优化师、合作者或观察者的，该账户的授权保留；销售改为空时只收回、不授予。③上线时按客户当前销售，给其名下全部账户补授权一次（S-22）。授权变化不改账户上的任何字段，也不影响在途审批单（R-12-015）。④授权弹窗里，客户当前的销售按「销售」只读显示、不能移除（同优化师）；可以再把他设为合作者或观察者，之后换销售时这个身份保留（按②保留授权）；移除合作者 / 观察者时，此人如果仍是客户销售，销售授权保留（D-02-15）。

2.6 账户「优化师」变更记录

2.6.1 功能描述

提成按业务日的历史归属算（D-00-72），11-提成中心要按业务日取账户当日的优化师（R-11-003）。本页负责把账户优化师的每次变化记下来；本页不新增展示界面。

2.6.3 业务规则

  • R-02-026 账户「优化师」每次变化都记录一条：变更前的值、变更后的值、生效时间。添加账户成功时记初始值（变更前为空），生效时间为添加成功时刻，和 R-02-011 同成同败；编辑账户信息弹窗保存成功（R-02-019）且优化师和原值不同时记一次变更，生效时间为保存成功时刻。保存失败、或优化师没变（只改了其他字段）时不记录。变更当天（UTC0）起归新优化师；上线时存量账户没有变更历史，上线前的日子一律按上线时的优化师（D-00-72）。账户添加成功前已经有消耗的日子，06 账单、10 利润照常计入（R-06-005）；提成归属按添加成功时记下的初始优化师、当日所属客户的销售（R-04-064）。优化师变化同时影响审批「绑定的运营」的解析（只影响之后提交的单，R-12-015）和客户可见范围（D-00-76、D-00-77）。记录供 11 按业务日取当日优化师（R-11-003），本页不新增展示界面。

2.6.6 验收标准

  • G-02-021 前置：账户 A 的优化师为王五（上线后添加账户时设定）。操作：2026-10-15（UTC0）在编辑弹窗把 A 的优化师改为赵六，点确认保存成功；再只改 A 的账户名称并保存。期望：系统能查到 A 的优化师变更记录：变更前王五、变更后赵六、生效时间为第一次保存成功的时刻（技术查库核验）；第二次保存没有新增变更记录；11-提成中心里 A 的 2026-10-14 归王五、2026-10-15 起归赵六（R-11-003）。
  • G-02-026（验证 R-02-026）前置：账户 D 在 2026-10-10 起已有消耗；2026-10-15（UTC0）添加进系统，初始优化师赵六，所属客户销售李明。操作：看 06 结算期 2026-10 的账单、10 利润与 11 提成。期望：06、10 的 D 包含 2026-10-10 起的消耗；11 中 D 的 2026-10-10～10-14 归优化师赵六、销售李明。

2.7 已禁用用户的显示与保留

2.7.3 业务规则

  • R-02-028 已禁用用户（D-00-83、D-02-12）：账户的优化师、合作者、观察者里已禁用的用户，在账户列表、编辑弹窗、授权弹窗回显为「姓名（已禁用）」，不显示用户ID。编辑保存时原值原样保留，不算一次变更（不写 R-02-026 变更记录），必填校验视为已填。主动改选时，候选只有启用用户；改掉以后不能再选回已禁用的人。

2.7.6 验收标准

  • G-02-025（验证 R-02-028）前置：账户 A 的优化师为王五，王五账号已禁用。操作：①打开 A 的编辑弹窗；②只改账户名称并确认；③再打开弹窗，展开优化师下拉，改选赵六并确认；④再展开优化师下拉。期望：①优化师显示「王五（已禁用）」；②保存成功，优化师仍为王五，没有新增优化师变更记录；③候选里没有王五，保存成功，记一条王五 → 赵六的变更；④候选里仍没有王五。
