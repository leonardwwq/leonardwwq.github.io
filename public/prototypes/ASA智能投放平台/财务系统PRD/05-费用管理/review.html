1 整体概述

1.1 背景与目标

现状：账户上只有一个「授信额度」字段；充值、退款靠线下对账，服务费按客户上的一个比例手算，规则变了说不清某笔钱按什么算；没有账户间调余额的手段，也没有统一的资金流水。

目标：

  • 预付款客户的每个账户有一个随消耗实时变化的余额；充值、退款、账户间余额分配、授信额度都走审批，钱按 03 的规则在提交那一刻算清并锁定。
  • 余额不足（含额度）时自动停投并通知销售与优化师，快用完时提前 7 天、3 天提醒。
  • 一个客户的所有资金变动在「交易明细」里一行一笔，可追溯到审批单。
  • 在客户上配置销售 / 优化师的提成规则，提交时选生效日期（当月 1 号起），审批通过后按所选日期生效，能看历史提成规则，供 11 计算。

可证伪的判定：给账户 A 充值 8,000.00 USD（第 2 行阶梯落 5.00%），审批通过后余额不变、交易明细出现「待完成」；09 确认收款后 A 余额 +8,000.00、额度清零、交易明细「已完成」；之后再退款 4,000.00，应退金额按 A 两笔充值各自的费率分别倒推。

2.1.3 业务规则

  • R-05-001 账户余额 = 该账户已到账的资金入账合计 − 已扣减的资金出账合计 − 截至当前的累计消耗；累计消耗只算该账户计费模式为预付款的结算期里的消耗（计费模式按结算期，D-00-73），后付款结算期的消耗不扣余额；消耗按最新消耗数据动态计算，历史某天的消耗被修正（如 10-21 发现 10-18 的消耗变了）时，余额随之变化，不另做冲正单据（D-05-02）；例外：预付改后付生效后，切换前的预付结算期已按 R-06-074 冻结欠费、或账单已结算冻结的，此后该结算期的消耗修正不再进入余额，也不再参与分桶覆盖，线下处理（R-05-118②、§5 已知限制）；计算实现由技术定
  • R-05-002 余额、充值金额、退款余额、取出余额、额度一律用账户消耗币种（D-05-09）；同一客户下所有账户消耗币种相同（D-05-11），正常流程不会产生同一客户多币种，02 开户时服务端校验客户与账户的账户系统一致（会议清单 D88）；账户消耗币种 = 账户所属账户系统的币种（技术答复 T07，原开放问题第 4 条关闭）；客户上的「币种」是客户给我们结算的币种，只用作充值 / 退款结算币种的默认值（R-05-028）
  • R-05-003 预付款客户的账户计余额、产生分桶，可充值、退款、余额分配。后付款客户（以当前结算期的计费模式为准，D-00-73）不能充值、退款、余额分配（D-05-03），账户不再产生新的分桶（在途单与结转见 R-05-118；生效时仍在审批中的 07 预付返点余额抵扣通过后照常成桶，R-05-118③）；仍有未用完分桶（账户余额 > 0）的账户，列表「账户余额」照常显示，否则显示「-」；剩余分桶按 R-05-118 用于后付结算单余额抵扣
  • R-05-004 资金入账有四种，每一笔按账户各生成一个「分桶」：①账户充值，09 收款单确认收款时到账（R-05-085）；②余额分配转入，审批通过时到账；③预付客户返点余额抵扣，07 审批通过时到账（D-00-19）；④账单结转：后付返点结转额挂起期间新出账的账单为预付款时，结转额充进对应账户余额（R-06-078、D-00-81）。分桶的入账时间 = 到账时间，金额 = 该账户本次进入余额的金额
  • R-05-005 每个分桶带一份费率快照（服务费率、税率、服务费税费承担方），退款、取出、余额抵扣时按它倒推（R-05-027）：账户充值、余额分配转入 = 提交时锁定的那套（R-05-029），提交当天没有适用规则时快照为服务费率 0、税率 0（R-05-017）；返点余额抵扣、账单结转 = 服务费率 0、税率 0（D-05-21），先去覆盖欠费时同样按 0（会议清单 D100，税务口径待财务确认）；上线前存量期初余额 > 0 的账户按 §4.1 建期初桶，快照按服务费率 0、税率 0（闭环清单 C01，D-05-53）
  • R-05-006 消耗从分桶里先进先出扣：按入账时间从早到晚，先扣满最早一桶再扣下一桶；入账时间相同按入账先后（D-05-07）；只扣预付款结算期的消耗（R-05-001），后付款期间分桶不被消耗扣，改回预付款后剩余分桶恢复按本条先进先出扣（D-00-73）；预付改后付生效后，切换前最后一个预付月在出账判结清或欠费冻结之前，分桶照常按本条覆盖该月消耗（含期间补报的消耗；释放的锁定分桶、新到账的充值同样参与），欠费冻结之后的该月消耗以及生效月起的消耗不再被分桶覆盖（R-05-118①、D-05-50）
  • R-05-007 退款、余额分配取出在提交审批时，06 后付结算单的余额抵扣在结算单提交时（D-00-73），按先进先出从「未锁定且尚有剩余」的分桶里锁定对应金额（D-05-06）：锁定部分不再被消耗占用，也不参与 06 预付账单的覆盖判定（D-00-11）；审批驳回、撤回或作废时释放；审批通过时从这些分桶里正式扣减（退款审批通过即扣，不等 09 确认汇出），扣减位置固定，之后消耗修正也不改它
  • R-05-008 锁定金额 = 该账户所有审批中的退款单、余额分配单与后付结算单余额抵扣锁定的合计；可用余额 = 账户余额 − 锁定金额；退款余额、取出余额的上限都是可用余额（D-00-52、D-00-54）
  • R-05-009 余额可以为负，为负即欠费（D-05-12）：消耗超出全部未锁定分桶的部分不属于任何分桶；之后新入账的分桶按先进先出先被这部分消耗占用。消耗修正导致余额变负时，不回退已完成的退款、余额分配。某日消耗是否已被分桶覆盖 = 本条与 R-05-006 先进先出的结果（锁定中的分桶不参与），06 据此逐张判断预付账单是否结清（D-00-11）；预付改后付后按 R-06-074 冻结欠费时，不属于任何分桶的那部分消耗按 R-05-118② 从余额计算中剔除
  • R-05-118 计费模式切换对余额的影响（D-00-73）：客户计费模式变更从确定时刻的次月 1 日（UTC0）生效（R-04-066）。预付改后付生效后：①该客户各账户未锁定的剩余分桶保留，生效月起的消耗不再扣它（R-05-006），账户余额照常显示（R-05-003）；切换前最后一个预付月在出账判结清或欠费冻结之前，分桶照常按先进先出覆盖该月消耗，包括期间补报的消耗、释放的锁定分桶、新到账的充值，欠费冻结之后不再覆盖（D-05-50）；06 生成后付结算单时按 R-06-076 自动带出「余额抵扣」（每账户上限为剩余应收，按先进先出取分桶，按 R-05-027 换算；余额抵扣金额以剩余应收为准，最后一桶本金 P = round2(所需金额 ÷ 该桶倍率)、不超过该桶剩余，倍率 = 1 + 税率 + 服务费率 + 服务费率 × 税率（公司承担时不加末项，R-05-021），税费、服务费、服务费税费按 R-05-027 正算，与所需金额的尾差计入该账户行余额抵扣的服务费，同 R-05-022；D-05-47④）；结算单提交时锁定所取分桶（R-05-007），审批通过时扣减，「余额抵扣账单」交易明细由 06 结算单审批通过时调用 05 写入（R-05-095），驳回、撤回、作废时释放；抵不完的留到下一张后付账单。②按 R-06-074 冻结欠费时，该账户该月不属于任何分桶的那部分消耗从余额计算中剔除，之后入账的分桶不再被它占用，这部分改由后付账单收取（D-05-47）；冻结的欠费在该客户下一张后付账单生成时挂上（R-06-074），挂上前客户又改回预付款的，解除冻结，欠费退回余额（这部分消耗重新计入余额，按 R-05-009 由分桶先进先出覆盖），原账单由 06 重新按 R-06-022 判结清；已冻结转入后付账单、或已结算冻结的切换前预付结算期，之后的消耗修正不再进入余额，也不再参与分桶覆盖，线下处理（§5 已知限制）（D-05-50）。③生效时仍在审批中的退款、余额分配照常走完，驳回、撤回释放的分桶按①保留；仍在途的账户充值照常走完，到账后成桶按①保留，后付款额度不因充值清零（R-05-012，D-05-47）；生效时仍在审批中的 07 预付返点余额抵扣，通过后按提交时的快照成桶（服务费率 0、税率 0），之后按①保留（D-05-50）。④改回预付款生效后，剩余分桶恢复按先进先出被消耗扣，可照常充值、退款、余额分配。⑤授信额度：切换生效时额度值、有效期、来源审批单原样保留；预付期设的有效期照常到期清零（R-05-011）；后付期不新设有效期（R-05-062）；跨切换生效才通过的额度调整，按通过那一刻客户当前结算期的计费模式写入，是后付款就丢弃有效期、只写额度，通过时为后付、有效期被丢弃的，不做 R-05-082 的有效期校验；改回预付款后按 R-05-011 判断「额度生效之后才提交的充值」时，额度生效时刻仍取写入该额度的原审批通过时刻（D-05-51）

2.2 授信额度、停投与提醒（定义）

2.2.1 功能描述

额度是兜底：预付款余额花完后还能用额度投；额度也用完就停投。后付款没有余额，额度是「未结清消耗」的上限。每天根据前一天消耗估算还能撑几天，快用完提前提醒。

账户额度（account_credit）：

2.2.3 业务规则

  • R-05-010 每个账户最多一条当前生效额度，额度只能通过「额度调整」审批写入（R-05-082）；没有额度或额度为 0 = 没有授信额度。账户上原有的「授信额度」老字段保留不用（D-02-02），存量老额度按 §4.2 导入（D-05-53）
  • R-05-011 预付款账户的额度有效期为空 = 长期有效；有效期到期（UTC0 有效期当天 23:59:59 之后）额度自动清零（预付期设的有效期，切换为后付款后照常到期清零，R-05-118⑤）；「账户充值」到账时，只有该充值单是在当前额度生效之后才提交的、且到账后该账户可用余额 > 0，额度才清零，否则额度保留，直到之后有一笔满足条件的充值到账或有效期到期（D-00-53）。余额分配转入、返点余额抵扣、账单结转不清零额度（D-05-20）；改回预付款后，「在当前额度生效之后才提交」中的额度生效时刻仍取写入该额度的原审批通过时刻（R-05-118⑤）
  • R-05-012 后付款期间不新设额度有效期（R-05-062），额度不因充值清零；没有有效期的额度不会自动清零，预付期设的有效期切换为后付款后照常到期清零（R-05-118⑤）
  • R-05-013 剩余额度：预付款 = max(0, 额度 + min(可用余额, 0))，即余额为正时等于额度，欠费后按欠费额递减；后付款 = max(0, 额度 − 未结清消耗)，不显示负数。未结清消耗按账户算、只算原始消耗（不含服务费、税费、服务费税费，不扣返点，不看结算单改过的应付）= 该账户在流转计费模式为后付款（R-06-012，即该结算期的计费模式，D-00-73）且尚未「已结算」的账单里的消耗，加上该账户尚未出账、且所属结算期计费模式为后付款的日子的消耗（含出账日前的上月日子）；切换前最后一个预付月在出账前由分桶覆盖（R-05-118①），不计入后付未结清消耗；承接了「上期预付欠费」（D-00-73②）的后付账单，其中欠费的消耗部分同样计入，直到该账单已结算；账单状态按 06（D-00-59、D-05-17）
  • R-05-014 停投条件（D-05-12）：预付款账户 可用余额 + 额度 ≤ 0；后付款账户 额度 > 0 且剩余额度 ≤ 0（未结清消耗按 R-05-013 的原始消耗）；后付款账户额度为 0 视为不限制、不因额度停投（D-05-24）；不另扣其他未到款项。判断时机：锁定与释放（退款、余额分配、后付结算单余额抵扣的提交、驳回、撤回、作废）、到账、额度写入与到期、消耗数据更新时即时判断，另有定时兜底（D-05-46）。满足条件时触发停投，停投执行动作沿用后端现有逻辑；条件不再满足时不自动恢复投放，由人工恢复（D-05-46，通知见 R-05-083）。停投不直接改客户状态，客户状态按 D-00-07 由消耗判定
  • R-05-015 触发停投时通知该客户的销售和该账户的优化师（D-05-18），通知渠道按 12（R-12-039），文案见 notifications「停投通知」；同一账户一次停投只通知一次
  • R-05-016 可用天数提醒：每个 UTC0 自然日拿到前一天消耗后计算一次 可用天数 = 可用资金 ÷ 昨日消耗（预付款可用资金 = 可用余额 + 额度；后付款只算额度 > 0 的账户，可用资金 = 剩余额度）；可用天数首次 < 7 时提醒一次，首次 < 3 时再提醒一次，同一天同时跨过两条线只发「不足 3 天」；可用天数回到 ≥ 7（或 ≥ 3）后对应那条线重新计数；昨日消耗为 0 或已停投不提醒（D-05-18）。收件人、渠道同 R-05-015，文案见 notifications「可用天数提醒」

2.3 计费口径（充值 / 退款 / 余额分配共用）

2.3.1 功能描述

钱怎么算：用哪天的哪条规则、哪一行、哪一档；已知净额正算、已知含费金额反算；四舍五入和尾差；账户币种转结算币种；退款 / 取出按分桶倒推；提交时全部锁定。弹窗只负责展示和收集，计算一律按本节。

公式（每个账户一行）：

  • 正算：税费 = B × 税率，服务费 = B × 服务费率，服务费税费 = B × 服务费率 × 税率（公司承担时为 0），应收 = B + 三项。
  • 反算：B = Y ÷（1 + 税率 + 服务费率 + 服务费率 × 税率），公司承担时分母不含最后一项。
  • 例（G-05-012）：A 第 38 天落第 2 行，应收 11,000.00；试高档 3.00%：B = 11,000.00 ÷ 1.0918 = 10,075.11 ≥ 10,000.00 成立；低档也成立，取高档。税费 604.51、服务费 302.25、服务费税费 18.14，合计 11,000.01，尾差 -0.01 计入服务费 → 302.24。

2.3.3 业务规则

  • R-05-017 取哪条规则：账户通过所绑登记表（02 registration_id）取 03 的规则，用「提交当天（UTC0）」的适用规则（R-03-003）。没有适用规则（账户没绑在线登记表，或提交当天早于第一条规则起始日期）时，服务费率、税率一律按 0 计算，该行税费、服务费、服务费税费均为 0.00，应收 / 实际金额 = 充值金额 / 充值余额；照常可提交，页面不另加提示（D-00-57、D-05-38）
  • R-05-018 服务费取哪一行时间区间：按提交当天是该账户消耗首日后的第几天，用 R-03-006 落行；账户还没有消耗首日时用第一行（D-00-58）
  • R-05-019 正算落档（已知充值金额 / 充值余额 B）：在该行服务费率里，固定比例直接用；阶梯比例用本次这一笔、这一个账户的 B 按 R-03-009 落档（左闭右开，不累进），「按月 / 按日统计」不作用于此（D-00-51）
  • R-05-020 反算落档（已知应收金额，或余额分配转入的实际金额 Y）：从最高档往最低档逐档试，按该档费率算 B = Y ÷（1 + 税率 + 服务费率 + 服务费率 × 税率）（公司承担服务费税费时不加最后一项），B 按 R-05-022 先舍入，落在该档 [下限, 上限) 内即用该档；高档、低档都成立时取高档（D-00-51，按到账净额判档，原「按应付判档」作废）；没有一档成立时该行标红、不能提交，提示「该金额无法对应服务费阶梯，可填小于 {甲} 或不小于 {乙}」（D-05-15）：甲 = 低档能成立的最大应收 + 0.01，乙 = 高档能成立的最小应收，由服务端试算接口按分求出返回，前端只展示（会议清单 D04）
  • R-05-021 金额拆分（每个账户一行）：税费 = B × 税率；服务费 = B × 服务费率；服务费税费 = B × 服务费率 × 税率（客户承担），公司承担时为 0（R-03-028）；应收 / 实际金额 = B + 税费 + 服务费 + 服务费税费
  • R-05-022 舍入：B、税费、服务费、服务费税费各自四舍五入到 2 位小数（D-00-13）；正算时应收 = 四项舍入后相加。反算时 B 先舍入，再按 R-05-021 算三项并舍入，四项之和与输入的 Y 差出的尾差全部计入服务费，Y 以输入为准；服务费率为 0 的行也照此计入，可能出现 ±0.01 的服务费（D-05-19）
  • R-05-023 所有金额输入框只接受数字和一个小数点：负号、字母输不进去，小数第 3 位按不下去；粘贴或自动填充的非法内容不写入，保留原值，并就地标红「请输入不小于 0、最多 2 位小数的金额」；任何情况下都不静默四舍五入或截断。其他校验（超过可用余额、反算无解等）一律在对应框就地标红（D-00-82）

  • R-05-027 退款、取出按分桶倒推（D-00-52、D-00-54）：按 R-05-007 先进先出锁定的每个分桶部分 P，用该分桶的费率快照算 P × 税率、P × 服务费率、P × 服务费率 × 税率；一个账户内各分桶的同类金额先相加再四舍五入到 2 位；应退金额 / 实际金额 = 退款余额 / 取出余额 + 税费 + 服务费 + 服务费税费。前端只展示账户合计，不展示分桶；这里与 06 按段 / 按天舍入不同是有意的，因为分桶不展示（D-00-13）。提交前的服务端预算与回显见 R-05-114

  • R-05-066 提成规则挂在客户上：每个客户一份，分「销售」「优化师」两套，每套 0 到多条规则；某账户在销售套里命中的规则用于该客户销售的提成，在优化师套里命中的规则用于该账户优化师的提成；提成金额怎么算、归谁、怎么展示归 11（D-00-38～D-00-41）
  • R-05-067 提成规则配置弹窗顶部「销售 / 优化师」两个切换，默认销售；两套一起编辑、一起提交成一张「提成规则配置」审批单，审批通过后整份替换该客户的两套规则（D-05-28）
  • R-05-068 打开时回填该客户当前生效版本（R-05-110）的两套规则，生效日期留空；没有当前生效版本（从没配过，或只有待生效版本）时每套各有 1 条空规则「提成规则1」。选了生效日期后，表单按该日期适用的版本（R-05-075）重新回填，没有适用版本时回填空规则；表单已经改过时先确认「将按 {日期} 适用的版本重新回填，当前修改会丢失」，取消则日期恢复原值、表单不动；回填后日期框下提示「已按 {日期} 适用的版本（{审批单号}）回填」（会议清单 D18-a）
  • R-05-117 待生效提示：该客户有待生效版本时，弹窗顶部提示「该客户有待生效的提成规则（{yyyy-mm-dd} 起），如需修改，请选择该生效日期提交，审批通过后覆盖」，有多个待生效版本时按生效日期升序列出（D-05-41，会议清单 D99）
  • R-05-069 每条规则标题「提成规则N」右侧「+」在最后追加一条空规则、「−」删除本条，删除后从 1 重排编号；每套可以删到 0 条，0 条时显示「暂无规则」和「+ 添加规则」；条数不设上限
  • R-05-070 适用账户必填复选，选项为该客户下全部账户（不按当前用户的账户查看权限过滤，避免整份替换时误删他看不到的账户，D-05-29），按账户名称升序，已停用账户名称后标灰字「已停用」、排在最后、不剔除；同一套里各条规则的适用账户不能重复，重复时提示「适用账户与提成规则{N}重复：{账户名称}」；每套底部灰字「以下账户未适用任何规则：{账户名称}」（全部账户都有规则时不显示），不拦提交，客户新开账户不另通知；没有被任何规则选中的账户不产生该角色的提成
  • R-05-116 空规则：适用账户未选、阶梯比例未填、提成上限为空的规则视为空规则，提交时忽略、不进审批单；只填了一部分的规则照常按必填校验在对应框标红、不能提交（会议清单 D18-c）
  • R-05-071 计算方式必填单选：毛利阶梯计算（基数 = 毛利，D-00-34）/ 服务费百分比（基数 = 服务费，不含税，D-00-39），默认毛利阶梯计算；选项后显示「单位：人民币」
  • R-05-072 每条规则一张阶梯表「下限 - 上限 比例%」，交互与校验同 03 的阶梯（R-03-023、R-03-024、R-03-026）：第一档下限 0、下一档下限 = 上一档上限、最后一档上限「不限」、左闭右开、至少 1 档；区间金额为人民币；比例 ≥ 0、最多 2 位小数、不设上限；阶梯怎么落档按 D-00-40（同一人、同一角色、同一月、同一版本内同一条规则的基数合计落一档、不累进），由 11 计算
  • R-05-073 提成上限选填，人民币，≥ 0、最多 2 位小数；为空 = 不封顶；含义 = 每个人每个自然月按这条规则算出的提成最多到该金额（D-05-08）；规则身份 = 一个版本里的一条规则，月中换版本时各版本分别封顶（D-00-40）；上限框旁释义「每人每自然月按本条规则封顶（人民币）；月中换版本时各版本分别封顶」
  • R-05-074 两套规则与当前生效版本或同生效日期的版本完全相同时也允许提交，不拦（D-05-39）；原型弹窗里隐藏的「投放应用（应用名称 / 应用ID）」面板是残留，不做（D-05-30）
  • R-05-075 提成规则版本：审批通过（R-12-025）时按业务单据快照写入一个版本，生效日期 = 提交时所选日期，写入时不再校验是否早于当月 1 号（跨月才通过的照常按所选日期写入）；该客户已有同生效日期、未覆盖的版本时，新版本替换它，旧版本变为已覆盖。某日适用版本 = 该客户未覆盖的版本里，生效日期 ≤ 该日、生效日期最大的那一个；没有则该日没有提成规则，不产生提成。生效日期早于审批通过当天时，从生效日期起的提成由 11 按新版本重算，已算完人员月的金额变化由 11 记变化记录、不锁（D-05-08、D-00-41）；版本只追加或覆盖，旧版本保留供 11 回溯
  • R-05-108 弹窗底部「生效日期」必填，销售、优化师两套共用一个；日期选择器只能选「当月 1 号」及以后（当月按 UTC0 今天所在月），不设最晚日期；为空提示「请选择生效日期」；所选日期早于今天（UTC0）时日期框下灰字「生效日期早于今天，审批通过后将从 {日期} 起按新规则重算提成」，不拦（会议清单 D19）；服务端提交时复核，早于当月 1 号提示「生效日期不能早于当月 1 号」（同 03 规则起始日期 R-03-033，D-05-08）；上线前导入的提成规则不受「最早当月 1 号」限制，生效日期 = 上线月 1 日（与 index S-18 同一个上线月配置），关联审批单号显示「上线导入」（§4.4，D-05-53）
  • R-05-109 选的生效日期与该客户某个未覆盖的版本相同时，日期框下方提示「该生效日期已有提成规则，审批通过后将覆盖原规则」，不拦提交；表单按该日期适用的版本回填（R-05-068）
  • R-05-110 版本状态由系统按日期计算、不能手动改（今天按 UTC0）：生效中 = 以今天计的适用版本（R-05-075）；待生效 = 生效日期晚于今天；已结束 = 生效日期早于生效中那一版；已覆盖 = 被同生效日期的新版本替换，不在历史提成规则展示、不参与适用判定，写入它的审批单照常可查。待生效版本不能撤销，要改就选同一个生效日期再提一版覆盖（D-05-41，提示见 R-05-117）

历史提成规则

  • R-05-111 弹窗表单下方「历史提成规则」区默认收起，点标题展开 / 收起；列出该客户全部未覆盖的版本，按生效日期降序；生效中、待生效的版本在生效日期旁打标签「生效中」「待生效」，已结束的不打标签；没有版本时展开显示「暂无历史提成规则」（同 03 历史规则 R-03-035，D-05-40）；有审批中提成规则单时只读打开的弹窗里照常可展开（R-05-077）
  • R-05-112 历史提成规则表列：生效日期（yyyy-mm-dd）、销售规则、优化师规则、关联审批单号；销售 / 优化师规则的文字格式同审批内容区（R-05-106），某套 0 条显示「无」；点关联审批单号新页打开写入该版本的审批单详情（查看判断按 R-05-086），上线导入的版本显示「上线导入」（R-05-108）；历史区只读、没有回填按钮，按所选生效日期回填见 R-05-068
  • R-05-119 提供给 11 的提成规则数据（11 X-4）：①版本写入时每条规则的序号（「提成规则N」）随版本固定，作为该版本内规则的稳定标识，之后不再变；编辑表单里删除后从 1 重排（R-05-069）只影响新提交的版本，跨版本本就不算同一条规则（D-00-40）；②每个未覆盖版本的生效区间 = [本版生效日期, 下一个生效日期更晚的未覆盖版本的生效日期)，最后一版到「不限」，按 R-05-075 计算；③该客户审批中的提成规则配置单的审批单号与所选生效日期，供 11 显示「规则审批中」提示（会议清单 D19）

2.10 提交审批与审批结果（5 类共用）

2.10.1 功能描述

5 个弹窗共用的提交、防重、服务端复核、审批结束后的数据变化，以及与 09 收付款的两个接口点。

2.10.3 业务规则

  • R-05-076 本页 5 种审批类型（R-12-001）：账户充值、充值退款、额度调整、余额分配、提成规则配置，审批事项都是「费用管理」
  • R-05-077 同一客户、同一审批类型同时最多 1 张审批中的单（D-00-14）：已有时点对应按钮不打开弹窗，弹提示框「该客户已有审批中的{审批类型}（审批单号 {单号}，申请人 {姓名}），请等审批结束或撤回后再操作」，点「知道了」关闭，单号可点、新页打开审批详情（句式与形态按 R-12-047）。例外：提成规则配置有审批中单时打开只读弹窗：顶部提示条「该客户提成规则有状态为审批中的修改未通过，此处展示当前生效中的信息。（审批单号 {单号}，申请人 {姓名}）」（形态按 R-12-047），两套回填当前生效版本且全部禁用，生效日期框与「提交审批」隐藏，历史提成规则照常可展开（D-05-45）。不同类型互不影响（退款、余额分配可同时审批中，各自锁定按 R-05-008 叠加）
  • R-05-078 点「提交审批」先做本弹窗的全部前端校验（有试算未完成时先等试算，R-05-113），任一不通过不提交，在对应位置提示；通过后弹二次确认框，标题「提示」（取消 / 确定）：账户充值、额度调整、提成规则配置为「{审批类型}需进行审批，是否提交审批单？」；充值退款、余额分配的确认框内容按 R-05-114 由服务端预算后回显；按服务端预算任一账户「提交后可用余额 + 额度 ≤ 0」时确认框加一句「提交后 {账户名称} 可用资金将 ≤ 0，账户会立即停投；审批驳回或撤回后不会自动恢复投放，需人工恢复。」（会议清单 D42）
  • R-05-079 确定后服务端复核：权限点（R-05-038）、当前结算期计费模式（R-05-003）、同类型审批中单（R-05-077）、所选付款主体 / 收款主体仍在客户当前生效的付款主体里（否则提示「付款主体已变更，请重新选择」，会议清单 D116）、提成规则生效日期不早于当月 1 号（R-05-108）、可用余额（R-05-053、R-05-056，按服务端最新数据）、汇率与计算结果（充值与转入侧 R-05-026，退款与取出侧 R-05-114）；任一不满足不创建审批单并提示对应文案，弹窗不关、已填内容保留；带在途单号的提示同 R-05-077；同一弹窗连续点击只提交一次，请求中按钮显示加载
  • R-05-114 退款 / 取出服务端预算与确认框回显（D-05-48）：充值退款、余额分配点提交审批后，先做前端校验，再由服务端按最新分桶预算（不建单）；确认框（标题「提示」）回显每个账户的退款 / 取出余额、税费、服务费、服务费税费、应退 / 实际金额和合计（余额分配另回显转入侧各行与可分配实际金额），与弹窗不同的行标黄并写「金额已按最新余额重算」；点确定后服务端再算一次：退款 / 取出余额 ≤ 最新可用余额、且结果与确认框一致时建单，不一致时刷新确认框请用户再确认，不关闭弹窗、不清空内容。标「全部退款」的行按提交时刻最新可用余额取值（R-05-052）。余额分配取出实际金额合计与页面不同时，差额并入转入侧最后一次点过「填入剩余」的那一行，没有这样的行时并入实际金额最大的转入行，再按 R-05-020 反算并在确认框回显；并入后该行反算无解时不建单，提示「取出金额已变化为 {x}，请调整转入金额后重新提交」，弹窗内容保留（会议清单 D07）
  • R-05-080 复核通过后提交审批（R-12-014）：操作对象客户 = 本客户；本单涉及账户（供「绑定的运营」按账户优化师解析，D-00-76）= 充值、退款、余额分配中填了金额的账户，额度调整的单内账户，提成规则配置为该客户名下全部账户；业务单据 = 弹窗全部内容 + R-05-029 的计算快照 + 提交时各账户可用余额；额度调整只把额度或有效期与提交时当前生效值不同的账户写进业务单据（服务端按提交时刻判断），并带上这些账户提交时的生效额度与有效期作为比对基准（R-05-104、D-00-75）；发起备注 = 弹窗里的「备注」（同时作为业务备注在审批内容区展示，D-05-31）。成功后按返回的审批单状态弱提示（文案按 R-12-018），关闭弹窗、刷新列表
  • R-05-081 退款、余额分配提交成功即按 R-05-007 锁定，并按 R-05-014 即时判断停投；其他类型提交不动余额
  • R-05-082 审批单变为已通过（R-12-025）时：账户充值 → 生成 09 的收款单（应收 = 应收金额总计（结算币种））并写一条「待完成」交易明细，余额此时不变；充值退款 → 审批通过即从锁定分桶扣减余额（不等 09 确认汇出）、生成 09 的付款单（应付 = 应退金额总计（结算币种））、写一条「待完成」交易明细；余额分配 → 取出部分扣减、转入部分按 R-05-004 到账（新分桶），写一条「已完成」交易明细；额度调整 → 只写入单内账户的额度与有效期（含额度为 0 的取消），单外账户的额度不动（包括审批期间被充值清零或已到期的）；提成规则配置 → 按 R-05-075 写入版本（按所选生效日期生效）（D-05-05）。生成收付款单时按 R-09-001、R-09-002 带：付款主体 / 收款主体、币种（= 本单结算币种）、备注（弹窗备注）、申请人、申请时间；账户充值另带打款凭证与账户行（本单每个填了金额的账户及其应收金额，账户币种）。最后一个审批人通过时业务执行失败按 R-12-045 回滚（D-00-79①）；本页只有一种执行失败：额度调整单内任一账户的额度有效期早于通过当天（UTC0），原因「额度有效期 yyyy-mm-dd 已过，请驳回后重新提交」（D-05-49；通过时为后付、有效期被丢弃的不做此校验，R-05-118⑤）；其余情形通过时不复核、不算失败：账户充值审批期间客户计费模式已改为后付款的照常通过（在途单照常走完，R-05-118），退款 / 取出已在提交时锁定，提成规则不复核生效日期
