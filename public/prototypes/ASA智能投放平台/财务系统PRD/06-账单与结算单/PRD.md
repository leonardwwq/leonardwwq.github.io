## 1 整体概述

### 1.1 背景与目标

现状：账单只有原型和一段注释，账单金额怎么来、预付和后付各怎么结、渠道统计金额为什么和账户加总对不上（苹果同一订单挂在多个账户下）、结算单和收款怎么衔接都没写清。

目标：
- 每个客户每个自然月一张账单，2 日自动出上月账单；一个结算期只有一种计费模式；后付按 03 规则算服务费、税费，预付按充值时锁定的分桶费率折算，金额和 05、03 同一口径。
- 后付款由人从账单生成结算单（可改应付、可换结算币种、自动带出余额抵扣），审批通过生成收款单，收款确认后账单结清；应付为 0 的结算单审批通过即结清；返点抵扣超出账单的部分结转到下期。预付款逐张账单判断是否被余额覆盖，覆盖完自动结清，欠费通知销售；改后付时没还清的欠费转入第一张后付账单收取。
- 渠道统计金额按订单号去重，内部能看到真实的消耗差额。

可证伪的判定：公共前置下 2026-10-02 出账，橙子 9 月账单总计 35,040.00 USD、第一层渠道统计金额 24,000.00（PR-0902 只算一次）；生成结算单选人民币，应付默认 249,603.94；审批通过后账单变「待支付」，09 确认收款后变「已结算」。

### 1.2 本页范围

- ✅ 包含：账单生成与金额口径；上期预付欠费；渠道统计金额与消耗差额；账单状态机、刷新与锁定、预付逐张结清与欠费通知；账单管理页（账单信息 / 已提交审批）；生成结算单弹窗（含余额抵扣、结转）与审批；审批内容区；05 费用明细 tab 的口径。
- ❌ 不包含：导出、账期计算（D-06-10）；收款确认与手续费（09）；返点金额计算（07）；渠道统计金额的抓取与上传（08）；交易明细实体与分桶本身（05）；审批引擎（12）。

### 1.4 术语定义

| 术语 | 释义 |
| --- | --- |
| 账单 | 一个客户一个 UTC0 自然月的费用汇总，每月 2 日出上月（D-00-10） |
| 结算单 | 由人从后付款账单手动生成的待付款单据，走「账单管理—生成结算单」审批，不单独设状态（D-00-60） |
| 流转计费模式 | 该结算期的计费模式（一个结算期只有一种，D-00-73），决定账单走预付还是后付流转（R-06-012） |
| 可结算应收 | 账户行应收加上期预付欠费；结算单的「预估应收金额」（R-06-013） |
| 上期预付欠费 | 预付改后付生效时没还清的预付账单欠费，冻结后按账户并入第一张后付账单（R-06-074） |
| 返点抵扣 / 余额抵扣 | 结算单里的两种抵扣行，名称固定：返点抵扣 = 本账单客户返点（07 后付余额抵扣计入的返点 + 结转额，不计到款）；余额抵扣 = 改后付后账户里剩下的余额按退款口径自动抵应收（计入到款，R-06-076）。与 07 兑现方式「余额抵扣」不是一回事 |
| 结转额 | 返点抵扣超出账单可结算应收的部分，结算单通过后挂到下一张后付账单（R-06-077、R-06-078） |
| 自接苹果 | 系统从苹果同步订单、按订单号结算的账户系统（由账户系统配置决定，D-06-31）；其他上游渠道只给金额 |
| 日汇率 | 当天 UTC 00:17 从系统汇率源取的那一次价格；结算锁定 4 位（D-00-74） |
| 在途结算单 | 审批中，或已通过但收款单未完成的结算单（D-00-61） |

### 2.1 账单与出账（定义）

其余金额字段见 2.2.2。

#### 2.1.3 业务规则

- **R-06-001** 账单按「客户 × UTC0 自然月」一张，结算期展示「yyyy-mm-01 至 yyyy-mm-最后一天」。当月从该客户第一天有任一账户消耗数据起就有一张「未出账」账单，金额随消耗实时变化；次月 2 日（UTC0）系统自动出账，账单变「待结算」，出账时刻由技术定；全月没有任何账户消耗数据的客户不生成账单（账单管理.html:3931 §2.4.1，D-06-13）。只出结算期 ≥ 上线月的账单，上线月与 07 计提、08、10、11 共用一个配置（index S-18；S-16 定为只从上线月起），上线月之前的结算期不出账单（D-06-36）。已知限制：客户全月零消耗、只有苹果订单或 08 入账时同样不生成账单，渠道金额在 08 / 10 查看（§2.1.5、index §2.9，D-06-45）
- **R-06-002** 第二层每个账户一行；同时满足以下条件的账户不展示：消耗、服务费、税费、服务费税费、客户返点、上期预付欠费都为 0，渠道统计金额为 0 或「-」，且没有订单行（D-06-33）；客户返点不为 0 的账户照常展示，应收为负也展示（R-06-011）；05 费用明细 tab、结算单弹窗明细、审批快照用同一口径
- **R-06-003** 账单币种 = 该客户账户的消耗币种（同一客户下所有账户相同，D-05-11）；账单里所有金额都用账单币种，千分位、2 位小数、后缀币种代码，格式同 R-05-033；前端只展示服务端返回的 2 位金额，不做二次舍入（D-00-13）；结算币种换算只发生在结算单（R-06-043）
- **R-06-004** 一个结算期只有一种计费模式：该结算期的计费模式 = 该结算期第一天（UTC0）客户生效的计费模式；04 的计费模式变更从确定时刻的次月 1 日（UTC0）起生效（预付改后付以审批通过时刻、后付改预付以保存时刻为准，D-00-73、R-04-023、R-04-024），结算期中途不切换（R-04-066），账单内不再按天区分预付日子、后付日子（D-06-12、D-06-24）

#### 2.1.5 异常与边界

| 场景 | 现象 | 系统行为 | 用户看到 |
| --- | --- | --- | --- |
| 全月没有消耗 | 客户该月无数据 | 不生成账单 | 列表里没有这一行 |
| 全月零消耗、只有苹果订单或 08 入账（已知限制） | 客户该月有渠道金额、没有消耗 | 不生成账单（R-06-001，index §2.9） | 06 没有这一行，渠道金额在 08 / 10 查看 |
| 结算期早于上线月 | 上线前的月份 | 不出账单（R-06-001，index S-18） | 列表里没有这些结算期 |
| 账户全月为 0 且无渠道数据、无订单 | 其他账户有数据 | 该账户不进第二层（R-06-002） | 第二层少这个账户 |
| 账户消耗为 0 但有订单或渠道金额 | — | 照常展示（R-06-002） | 一行 0.00 消耗、有渠道统计金额 |
| 2 日出账任务失败 | 账单仍未出账 | 由技术重跑，出账时间以实际为准 | 仍显示「未出账」 |
| 结算期中途改计费模式 | 04 审批通过 / 保存 | 次月 1 日起生效，本结算期不变（R-06-004） | 本月账单仍是原计费模式 |

#### 2.2.3 业务规则

- **R-06-005** 消耗金额 = 该账户本结算期内每个 UTC0 自然日的消耗之和，消耗数据来源沿用现有；历史消耗被修正时按 R-06-019 / R-06-020 决定账单变不变
- **R-06-006** 账户行三项费用：流转计费模式为预付款的账单按 R-06-007 算，后付款的按 R-06-008 算；第一层各金额 = 本账单全部账户行（含当前用户看不到的）之和，渠道统计金额例外（R-06-016）；舍入点按 D-06-19（D-00-13）：中间值可以存更高精度，但不能拿高精度值直接加总代替舍入点
- **R-06-007** 预付款账单：按 05 的先进先出（R-05-006），本结算期消耗从哪些分桶扣、各扣了多少 P，就用该分桶的费率快照（R-05-005）算：服务费 = P × 服务费率，税费 = P × 税率，服务费税费 = P × 服务费率 × 税率（快照为客户承担时；公司承担为 0）；锁定中的分桶（审批中的退款、余额分配、余额抵扣占住的，R-05-007）不参与覆盖；返点余额等 0 费率分桶覆盖的消耗服务费、税费按 0，覆盖欠费时同样按 0（D-05-21）；超出全部可用分桶的欠费消耗（R-05-009）先按该日 03 规则用 R-06-008 的算法暂算（阶梯落档时用该段全部消耗落档取比例，按日统计时用当天全部消耗，比例只乘欠费部分；欠费部分的各项各自四舍五入到 2 位，D-06-39），之后有新分桶按先进先出覆盖它时，改按新分桶的快照重算（账单待结算、未锁定、欠费未转入后付账单时生效，R-06-019，D-06-03、D-06-20）；每个分桶的扣减段各自四舍五入到 2 位再相加（D-06-19）
- **R-06-008** 后付款账单：逐日取 03 的适用规则（R-03-003；已出账月份重算时以该月出账时刻为 t，R-06-019）与服务费时间区间行（R-03-005、R-03-006；消耗首日首次确定后冻结，早于首日的日子落第 1 行，D-00-56）；把适用条款相同（服务费规则与税率完全相同，D-00-55）且落在同一行时间区间里的连续日子归成一段：固定比例 → 服务费 = 段内消耗 × 比例；阶梯 + 按月统计 → 段内消耗加总后按 R-03-009 落档 × 档位比例（落档用未舍入的原始消耗合计，D-00-13）；阶梯 + 按日统计 → 每天单独落档 × 比例（R-03-010）；税费 = 消耗 × 该段税率；服务费税费 = 服务费 × 税率（客户承担，R-03-028），公司承担为 0；按段（按日统计时按天）各项四舍五入到 2 位后相加（D-06-19）
- **R-06-009** 没有适用规则的日子（账户没有任何规则配置，或早于第一条规则起始日期）服务费率、税率按 0：服务费、税费、服务费税费为 0，照常出账、照常结算，不标异常、页面不加提示（D-00-57、D-06-08）；按 0 计的日期范围记在账户行的「无适用规则的日子」里供技术排查与 S-1 导入核对，页面不展示
- **R-06-010** 客户返点（后付款账单）= 以下两项之和，按账户加到对应账户行：①07 里「纳入扣减月份」选了本结算期、审批已通过、合计 > 0 的客户返点（R-07-036、R-07-037）；②挂到本账单的结转额（R-06-078）；两项在账户行上分开记录（结转额不是本月新增的返点成本，10 不重复计），账户行应收因此可为负（D-07-16）。「返点时间范围」= ①所属的消耗日期段每段一行「yyyy-mm-dd 至 yyyy-mm-dd」，②每笔一行「yyyy-mm 结转」（yyyy-mm 为来源账单结算期）；都没有显示「-」。预付款的返点在 07 审批通过时直接充进余额（D-00-19），流转计费模式为预付款的账单「客户返点」「返点时间范围」都显示「-」（D-06-11、D-00-18）
- **R-06-011** 账户行 应收金额 = 消耗金额 + 服务费 + 税费 + 服务费税费 − 客户返点；第一层「总计」= 各账户行应收金额之和（不去重，D-06-02）；账户行应收、总计、可结算应收都可能为负（返点按账户加，D-07-16；审批期间账单变小，D-00-67），生成结算单时可结算应收为负的按 R-06-077 结转
- **R-06-012** 账单走哪条流转按「流转计费模式」= 该结算期的计费模式（R-06-004，已出账、未出账一样）：预付款走 R-06-021，后付款走结算单（R-06-040 起）（D-06-12）
- **R-06-013** 可结算应收：账户行可结算应收 = 该账户行应收金额 + 该账户挂到本账单的上期预付欠费（R-06-074）；账单可结算应收 = 各账户行可结算应收之和，没有上期预付欠费时 = 总计。结算单的「预估应收金额」、07 纳入扣减月份的比较（R-06-024）都取账单可结算应收
- **R-06-074** 上期预付欠费：客户预付款改后付款生效后（D-00-73），流转计费模式为预付款、仍未结清的账单，把欠费冻结并入该客户第一张后付款账单：①冻结时点：生效时已出账且待结算的，在生效时刻冻结；生效时还没出账的（切换前最后一个预付月份），按 R-06-021 出账时判一次，没结清就在出账时冻结；生效后到该月出账判结清或冻结之前，分桶照常按先进先出覆盖该月消耗，包括期间补报的消耗、释放的锁定分桶、新到账的充值；欠费冻结之后的消耗、生效月起的消耗不再被分桶覆盖（D-06-37）；②冻结金额按账户算 = 该账户未被分桶覆盖的消耗 + 这部分按 R-06-007 暂算的服务费、税费、服务费税费（落档与舍入按 R-06-007），冻结后不再随分桶覆盖、消耗修正变化；已冻结转入后付账单、或已结算冻结的切换前月份，之后的消耗修正不再进入余额，也不再参与分桶覆盖，不改账单，线下处理（index §2.9，D-06-38）；③承接账单 = 该客户生效月的账单（该月没有账单时顺延到之后第一张后付款账单），在承接账单生成时挂上（冻结时承接账单已生成的即刻挂上）：对应账户行加一项「上期预付欠费（yyyy-mm）」= 冻结金额，每个来源结算期一行，计入账户行可结算应收（R-06-013），不计入总计，账户行当月没有消耗也照常展示；④原预付账单保持「待结算」、金额冻结；挂上前状态副标显示「欠费待转入下一张后付账单」，挂上后改为「欠费已转入 yyyy-mm 账单」，冻结期间不按 R-06-022 判结清；承接账单变「已结算」时（R-06-051 ③、R-06-053）一起变「已结算」并记结算时间（D-06-27）；挂上前客户又改回预付款（改回预付生效时承接账单仍未生成）的，解除冻结，欠费退回余额，原账单重新按 R-06-022 判结清（D-06-38）

### 2.3 渠道统计金额与消耗差额

#### 2.3.1 功能描述

内部对账用的两列：账户系统是自接苹果的，按订单号算并在第一层去重；其他渠道取 08 的数据。

#### 2.3.2 核心字段

| 字段名 | key | 类型 | 必填 | 枚举/取值 | 默认值 | 规则说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 渠道统计金额 | channel_amount | decimal(2) 账单币种 | 否 | 未取到为空 | — | R-06-014～R-06-016 |
| 消耗差额 | consumption_diff | decimal(2) 账单币种 | 否 | 可为负 | — | R-06-017 |
| 订单号 | order_no | string | 是 | 苹果 PR 单据号 | — | 第三层首列；可在多个账户下出现（R-06-015、R-06-028） |
| 订单总计 | order_total | decimal(2) | 是 | — | — | 渠道统计金额取它（币种不同时取折算值，R-06-015） |

订单行其余字段（付款参考编号、账单、账单类型、产品或广告主、描述、发票、截止日期、小计、税费）沿用现有（D-06-10），税费显示口径见 R-06-028。

#### 2.3.3 业务规则

- **R-06-014** 渠道统计金额与消耗差额只是内部对账用，不影响任何应收（D-06-05）；数据来源：自接苹果的账户系统（系统从苹果同步订单、按订单号结算的账户系统，由账户系统配置决定，D-06-31）取第三层订单数据，其他上游渠道取 08 按「账户 × 结算期」提供的上传来源渠道统计金额（R-08-018 的总计，R-08-090；D-00-24、D-00-26）；还没有数据时显示「-」，数据到了自动更新（§2.4 注）
- **R-06-015** 自接苹果：LOC 订单按「账单月份」落到 UTC0 自然月，没有账单月份的 CC 订单按交易日落月；订单币种与账户消耗币种不同时，LOC 订单按截止日期当天、CC 订单按交易日当天的日汇率（D-00-74）折成账户币种后计入；截止日期晚于今天时先按最近一天的日汇率暂折，截止日当天汇率入库后重折一次，之后不再变（同 08 R-08-017，D-06-46）；账户行渠道统计金额 = 该账户下本结算期订单行「总计」（折算后）之和；同一订单号挂在多个账户下时，每个账户下都展示一次、各自计入本账户行（D-06-04）；共享订单在订单号旁标注：同一张账单内共享写「与 {账户名称} 共享，各账户全额列示，第一层只算一次」，与其他客户的账户共享写「与其他客户账户 {账户名称} 共享，本账单全额计入」（D-06-31）
- **R-06-016** 第一层渠道统计金额只来自本账单列出的账户行（含当前用户看不到的，按 R-06-002 的展示条件）：自接苹果 = 这些账户下全部订单行按订单号去重后的「总计」之和，因此可能小于账户行之和；其他上游渠道（没有订单号）= 各账户行直接相加；去重范围只在同一张账单内（同客户、同结算期），不跨客户、不跨结算期（D-06-04）
- **R-06-017** 消耗差额 = 本层消耗金额 − 本层渠道统计金额（账户行用账户行的，第一层用第一层去重后的）；渠道统计金额为「-」时消耗差额也为「-」（D-06-05）；表头说明见 R-06-027
- **R-06-018** 渠道统计金额、消耗差额不受锁定：任何状态下都随订单数据或 08 数据更新（D-06-17）

### 2.4 状态、刷新与锁定（定义）

#### 2.4.1 功能描述

账单状态机，以及账单什么时候跟着数据变、什么时候锁死。

#### 2.4.3 业务规则

- **R-06-019** 未锁定的账单随最新数据刷新：未出账；以及待结算且没有审批中结算单的账单。触发刷新的变化：消耗修正、07 返点纳入本月扣减审批通过、预付分桶覆盖关系变化（R-06-007）、结转额挂上（R-06-078）、上期预付欠费并入（R-06-074）；已出账月份重算时以该月出账时刻为 t 取适用规则（R-03-003、D-03-24），出账后才通过的规则不回改该月；刷新只重算金额，不改变状态（D-06-06）
- **R-06-020** 结算单提交成功时，账单第一、二层金额（渠道两列除外）锁定为结算单快照（R-06-049），页面展示快照值，第一层总计旁标「已锁定」，悬浮「金额为结算单提交时的快照」；驳回 / 撤回 / 作废时解除锁定、按最新数据刷新；审批通过后一直锁定（待支付、已结算）。预付款账单变已结算时按当时的金额冻结。锁定或冻结后的消耗修正不回改账单，也不补差（D-06-06、D-06-18）；已知限制（收进 index §2.9）：预付账单已结算冻结后再有消耗修正，只改 05 的余额、不改账单，两边金额可能不一致；预付改后付的切换前月份按 R-06-074 ② 处理（消耗修正不进余额、线下处理）
- **R-06-021** 预付款账单出账时判一次结清：出账时有挂起的结转额要入桶的（R-06-078），先入桶，再判结清、决定是否发欠费通知（D-06-41）；该结算期内全部消耗都已被分桶按先进先出覆盖（锁定中的分桶不参与覆盖，R-06-007）→ 直接变「已结算」；否则保持「待结算」、按 R-06-075 显示欠费副标，并给客户的销售发一次欠费通知（D-00-11、D-06-22）；只看本张账单，与其他月份、其他账户的余额无关
- **R-06-022** 预付款「待结算」账单（欠费未转入后付账单的）在之后每次分桶覆盖关系变化（充值到账、余额分配、返点余额抵扣、锁定释放、消耗修正）以及每个 UTC0 自然日再判一次，满足 R-06-021 的结清条件即变「已结算」并冻结；逐张判断，早月份先结清不用等晚月份（D-00-11、D-06-07）
- **R-06-023** 预付款账单不显示「生成结算单」，任何状态都不能生成结算单（D-06-07）
- **R-06-024** 可被 07 选为「纳入扣减月份」的账单（R-07-036）：流转计费模式为后付款、状态待结算、没有审批中的结算单、没有被其他审批中且合计 > 0 的客户返点单选为扣减月份（同一张账单同一时间最多 1 张，D-00-18）；未出账月份不可选；本次返点 ≤ 该账单当前可结算应收（D-00-18），只校验整单合计，账户行应收因此为负也允许（D-07-16）；选项与可结算应收由服务端下发；只在 07 提交时校验，最后一个审批人通过时不再复核、照常生效（D-00-67），之后生成结算单时可结算应收为负的按 R-06-077 结转；通过后返点按账户加到对应账户行（R-07-037、R-06-010）
- **R-06-075** 预付款待结算账单的状态副标：有未被分桶覆盖的消耗时显示「欠费 x {账单币种}，待充值」，x = 未被分桶覆盖的消耗 + 其按 R-06-007 暂算的服务费、税费、服务费税费之和（落档与舍入按 R-06-007），随覆盖关系变化；欠费已冻结、承接账单还没挂上的显示「欠费待转入下一张后付账单」，已转入后付账单的显示「欠费已转入 yyyy-mm 账单」（R-06-074）（D-00-11）

#### 2.4.4 状态与流转

账单状态清单：未出账、待结算、待支付、已结算（D-00-59）。

| 当前状态 | 触发动作 | 操作者 | 目标状态 | 前置条件 |
| --- | --- | --- | --- | --- |

| 未出账 | 次月 2 日出账，预付且消耗全部被分桶覆盖 | 系统 | 已结算 | R-06-021 |
| 待结算 | 预付：本账单消耗全部被分桶覆盖 | 系统 | 已结算 | R-06-022 |

| 待结算 | 后付：结算单审批通过、应付 > 0 | 系统 | 待支付 | R-06-051 |

#### 2.4.5 异常与边界

| 场景 | 现象 | 系统行为 | 用户看到 |
| --- | --- | --- | --- |

### 2.6 生成结算单

#### 2.6.1 功能描述

后付款待结算账单的行操作，打开弹窗确认金额（含自动带出的余额抵扣、结转提示）、选结算币种与付款主体、可改应付，提交「账单管理—生成结算单」审批。

#### 2.6.3 业务规则

- **R-06-040** 「生成结算单」按钮：没有「账单管理（查看）」或「生成结算单」权限点（D-13-01）、流转计费模式为预付款、或状态不是待结算时不显示；其余情况显示，下列任一条件成立时置灰并悬浮显示原因，同时有多条时只显示优先级最高的一条：①「该账单已有审批中的结算单 {审批单号}」；②「有审批中的返点抵扣单 {审批单号}，审批结束后可生成」（07 选了本结算期扣减、合计 > 0、仍在审批中的客户返点单，D-06-23、R-07-053）；③「另有 N 个账户无查看权限，不能生成」（D-06-15）；单号可点，新页打开审批详情（D-06-32）
- **R-06-041** 生成结算单弹窗：标题「生成结算单」，右上角 ✕ 关闭，底部只有「提交审批」；只读信息 公司名称、结算期、预估应收金额（= 账单可结算应收，R-06-013）、消耗金额、税费、服务费、服务费税费、返点抵扣（= 账单客户返点合计，R-06-010）、上期预付欠费（有时）、余额抵扣（有时，R-06-076）（账单币种；两种抵扣行名称固定为「返点抵扣」「余额抵扣」）；可结算应收为负时显示结转提示（R-06-077）；下方带本账单第一、二层只读明细（同 R-06-027、R-06-028，有余额抵扣时账户行多一列「余额抵扣」，不带勾选框）
- **R-06-042** 结算币种（原型字段名「结算货币」，统一叫结算币种，D-00-68）：必选，下拉单选 人民币 / USD / USDT，默认客户的币种，客户币种为空时没有默认值（R-04-011）；原型占位里的「美元」不做（D-00-08） <!-- alias-ok -->
- **R-06-043** 结算币种与账单币种相同时汇率为 1、不显示汇率；不同时显示「汇率：1 {账单币种} = x {结算币种}（yyyy-mm-dd）」，x = 当天（UTC0）日汇率四舍五入到 4 位，显示与计算都用这 4 位；日期 = 实际取到的那天（当天没有、向前取最近一天时显示那一天）（D-00-74、D-00-62）；提交时服务端按提交当天重新取并锁定，与弹窗不同时按 R-06-048 ② 请用户确认；汇率与汇率日期随单进快照；取不到任何汇率时不能提交，提示「未取到 {账单币种}→{结算币种} 汇率，请稍后再试」
- **R-06-044** 应付金额（结算币种）：必填，默认 = （预估应收金额 − 余额抵扣）× 汇率，四舍五入到 2 位；可以改，不设上限；输入按 D-00-82：输入框只接受数字和一个小数点：负号、字母输不进去，小数第 3 位按不下去；粘贴或自动填充的非法内容不写入、保留原值，并就地标红「请输入不小于 0、最多 2 位小数的金额」；任何情况下都不静默四舍五入或截断；输入框下显示「默认 {默认应付} {结算币种}」，应付 ≠ 默认时再显示「已调整 {应付 − 默认}」（带正负号）；切换结算币种时按新汇率重新带出默认值、覆盖已改的值（D-06-09、D-06-21）；预估应收金额为负时按 R-06-077 固定 0.00、只读
- **R-06-045** 付款主体：必选，下拉单选，选项 = 该客户当前生效的付款主体；「+ 新增付款主体」、客户没有付款主体、有审批中的付款主体变更、新增提交后的提示与「需审批通过后可选」灰字，做法全部同 05 R-05-042（调起 04 付款主体弹窗、走付款主体变更审批、通过前不在选项里、仅「客户管理-读写」可见）（D-06-21）
- **R-06-046** 备注：多行，长度上限沿用现有备注输入框；应付金额 ≠ 默认应付时必填，未填提示「修改了应付金额，请在备注中说明原因」，其余情况选填；即审批发起备注，同时在审批内容区展示（同 D-05-31 做法，D-06-09）
- **R-06-047** 点「提交审批」校验结算币种、应付金额、付款主体、备注（R-06-046），不通过在对应位置提示；通过后二次确认，标题「提示」（同 R-05-078），文案「生成结算单需进行审批，是否提交审批单？」（取消 / 确定）
- **R-06-048** 确定后服务端复核：「账单管理（查看）」与「生成结算单」权限点、R-06-040 的全部条件、所选付款主体仍在客户当前生效的付款主体里、汇率、账单金额与余额抵扣与弹窗展示一致。①账单或余额抵扣在弹窗打开期间变了：不建单、弹窗不关，按最新数据就地重载：保留结算币种、付款主体、备注；值没变的行原样保留，值变了的行标黄「系统计算值已由 X 变为 Y」；应付金额用户没改过的跟随新默认值，改过的保留用户填的值；顶部提示「数据已更新，请核对后重新提交」，用户再点一次提交才建单；②提交当天汇率与弹窗不同：不建单，返回新汇率，弹确认「汇率已更新为 1 {账单币种} = x {结算币种}（yyyy-mm-dd），换算后金额 {Y}，是否按新汇率提交？」，Y = 按新汇率算的默认应付；用户改过应付的保留其值，确认框里同时列出新的默认值；点确定后按新汇率建单（D-06-30）；③付款主体已不在选项里：提示「付款主体已变更，请重新选择」；④已有在途结算单（句式按 R-12-047）：审批中的用提示框（「知道了」）「该账单已有审批中的生成结算单（审批单号 {单号}，申请人 {姓名}），请等审批结束或撤回后再操作」，已通过、收款单未完成的「该账单已有处理中的结算单（收款单 {财务ID}，待完成），待收款完成后再操作」；单号可点、新页打开审批详情，无查看权限按 R-12-043；⑤R-06-040 ②③ 任一在复核时成立（弹窗打开期间出现审批中的返点抵扣单、可见账户变化）：不建单，提示框显示对应的置灰原因原文，单号可点（D-06-44）；同一弹窗连续点击只提交一次，请求中按钮显示加载
- **R-06-049** 复核通过后提交「账单管理—生成结算单」审批（R-12-001、R-12-014）：操作对象客户 = 本客户；涉及账户 = 本账单第二层全部账户（D-00-76）；业务单据 = 弹窗全部内容 + 汇率与汇率日期 + 默认应付金额 + 余额抵扣明细（每个账户取用的分桶与金额，R-06-076）+ 结转额（有时，R-06-077）+ 账单第一、二层全部金额快照（含当前用户看不到的账户行）；发起备注 = 备注。成功后按 12 R-12-018 给弱提示（审批中「已提交审批」；免审直接通过「提交成功，无需审批，已生效」）、关闭弹窗、账单按 R-06-020 锁定、余额抵扣的分桶锁定（R-06-076）
- **R-06-076** 余额抵扣（后付）：生成结算单时客户当前生效的计费模式为后付款、且账单可结算应收 > 0 时，系统按账户自动带出「余额抵扣」，只读：每个账户 = min(该账户行可结算应收（< 0 按 0）, 该账户未锁定分桶按退款口径 R-05-027 折算的应退金额)；按先进先出取分桶，分桶余额与应退金额之间的换算同 R-05-027；余额抵扣金额以剩余应收为准，最后一个分桶只取够抵的部分，取用本金与尾差按 R-05-118 ①（本金 = round2(所需金额 ÷ 倍率)，不超过该桶剩余；尾差计入服务费，同 R-05-022，D-06-46）；余额抵扣之和不超过账单可结算应收，超出时从余额抵扣最大的账户行减回（相同按账户名称升序取第一个）（D-06-35）；返点抵扣（= 客户返点，R-06-010）先扣，余额抵扣在其后；提交成功时锁定所取分桶（同退款，R-05-007），驳回、撤回、作废时释放；审批通过时扣减这些分桶，并按 05 写一条「余额抵扣账单」交易明细（取值以 R-05-095、R-05-097 为准：充值金额 = −扣减的分桶金额之和，应付、实收、手续费显示「-」，关联账单 = 被抵扣的本账单）；余额抵扣算客户已付款（计入到款），与返点抵扣（不计到款）分开记录；抵不完的余额留在分桶里供下一张后付账单；客户改回预付后剩余分桶恢复先进先出（D-00-73、D-06-27）
- **R-06-077** 可结算应收为负：生成结算单时账单可结算应收 < 0 → 应付金额固定 0.00、只读，不做余额抵扣，不要求备注；结转额 = −可结算应收（账单币种）；弹窗与审批内容区显示「本次抵扣 {返点抵扣 − 结转额}，剩余 {结转额} 结转至下期」；结转额在审批通过时生成（R-06-078），驳回、撤回、作废不生成；只有这一种情况能产生结转，人工把正数应付改成 0 不产生结转（D-00-81、D-06-28）
- **R-06-079** 待结算返点提示：打开生成结算单弹窗时，该客户在 07 还有状态为「待结算」的客户返点计提项的，顶部黄条提示「该客户还有待结算的客户返点 {合计} {币种}（{结算期，多个用「、」分隔}），生成结算单后不能再抵扣本账单，可在返点管理里抵扣其他账单或现金打款」，合计取 07 计提项金额（R-07-011）；只提示、不拦提交（D-06-34）

### 2.7 审批结果

#### 2.7.1 功能描述

结算单审批结束后账单、收款单、分桶、结转额、交易明细怎么变。

#### 2.7.3 业务规则

- **R-06-050** 审批流 0 节点或全部节点被跳过时提交即通过（R-12-018），立即按 R-06-051 处理
- **R-06-051** 审批单变为已通过（R-12-025）时：①余额抵扣 > 0 的按 R-06-076 扣减分桶；有结转额的按 R-06-078 处理；②应付金额 > 0：生成一张 09 收款单（交易类型 结算单支付，应收 = 应付金额，币种 = 结算币种，付款主体，关联本结算单与账单；另带账单第二层每个账户行及其本次应收 = 账户行可结算应收 − 余额抵扣，即扣完返点抵扣、余额抵扣、含上期预付欠费后的剩余应收（账单币种，作为 09 手续费分摊权重，R-09-002；本次应收 ≤ 0 的账户行分摊权重按 0，本次应收照原值记录，D-06-42））；按 R-05-094 写一条「结算单支付」交易明细（待完成）：发起时间 = 申请时间，充值金额显示「-」（余额不变），应付金额 = 应付金额（结算币种），账户列表每个账户一行「{账户名称} {本次应收} {账单币种}」，关联审批单号、关联账单 = 本结算期，备注 = 备注；账单变「待支付」（D-00-59）；③应付金额 = 0.00（返点抵满、结转、余额抵扣抵满、人工改为 0）：不生成收款单、不写「结算单支付」交易明细，账单直接变「已结算」，结算时间 = 审批通过时间（D-00-80、D-06-29）；每张结算单都记审批通过时间，与默认应付（= 改前应收，已扣返点抵扣、余额抵扣）、应付、各账户行本次应收一起供 10 取数；④按 R-12-045 列明本包的最终通过执行失败情形：没有——通过时不复核账单金额、付款主体与分桶（分桶提交时已锁定），技术异常按 12 处理（D-00-79）
- **R-06-052** 审批单变为已驳回、已撤回或被作废（作废效果同撤回，R-12-046、D-00-79）：账单留在「待结算」、解除锁定、释放余额抵扣锁定的分桶、不生成结转额、按最新数据刷新，「生成结算单」重新可用；原单不能修改重提（R-12-034）
- **R-06-053** 09 收款单确认收款（已完成）时：账单变「已结算」并记结算时间（欠费转入本账单的预付账单一起变已结算，R-06-074）；对应交易明细由 05 按 R-05-095 变已完成；实收、手续费由 09 记录（D-00-32）。本期收款单不作废、不退回（D-00-69）；已知限制：客户一直不付时收款单一直待完成，账单一直「待支付」、不能重新生成结算单（R-09-075、D-00-61）
- **R-06-078** 结转额挂载：审批通过时把结转额按原账单里可结算应收为负的账户行、按各行可结算应收负数大小占比拆到账户（D-06-40），四舍五入到 2 位，尾差给负数最大的那行；每个账户的结转额挂到该客户最早一张流转计费模式为后付款、待结算、未锁定的账单（不挂未出账账单），计入该账户行「客户返点」、返点时间范围加一行「yyyy-mm 结转」（R-06-010），目标账单按 R-06-019 刷新；当时没有这样的账单就挂起，原账单「客户返点」旁显示「待结转 {金额}」；挂起期间一旦出现符合条件的后付账单（新出账，或被驳回 / 撤回解锁）就挂上；挂起期间新出账的账单流转计费模式为预付款时，结转额在出账时按 0 费率充进该账户余额（05 入桶来源「账单结转」，R-05-004），先入桶再按 R-06-021 判结清、决定是否发欠费通知（D-06-41），由本页写一条「客户返点」交易明细（已完成，备注「yyyy-mm 账单结转」，各列取值按 R-05-095、R-05-097）；目标账单之后生成结算单时可结算应收又为负的，按 R-06-077 继续结转；已知限制：客户之后再没有账单时结转额一直挂起（D-00-81、D-06-28）

- 结算单快照只追加不改；账单每次锁定、解锁、状态变化、欠费冻结转入、结转挂载可追溯到审批单或收款单。
- 后付账单规则判定调用 03（T-03-002），预付账单分桶扣减与余额抵扣的分桶锁定 / 扣减调用 05（T-05-001），不另写。
- 实现任务：T-06-001～T-06-009，见 spec.yaml。
