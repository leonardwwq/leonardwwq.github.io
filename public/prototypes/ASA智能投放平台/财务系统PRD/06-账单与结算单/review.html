1 整体概述

1.1 背景与目标

现状：账单只有原型和一段注释，账单金额怎么来、预付和后付各怎么结、渠道统计金额为什么和账户加总对不上（苹果同一订单挂在多个账户下）、结算单和收款怎么衔接都没写清。

目标：

  • 每个客户每个自然月一张账单，2 日自动出上月账单；一个结算期只有一种计费模式；后付按 03 规则算服务费、税费，预付按充值时锁定的分桶费率折算，金额和 05、03 同一口径。
  • 后付款由人从账单生成结算单（可改应付、可换结算币种、自动带出余额抵扣），审批通过生成收款单，收款确认后账单结清；应付为 0 的结算单审批通过即结清；返点抵扣超出账单的部分结转到下期。预付款逐张账单判断是否被余额覆盖，覆盖完自动结清，欠费通知销售；改后付时没还清的欠费转入第一张后付账单收取。
  • 渠道统计金额按订单号去重，内部能看到真实的消耗差额。

可证伪的判定：公共前置下 2026-10-02 出账，橙子 9 月账单总计 35,040.00 USD、第一层渠道统计金额 24,000.00（PR-0902 只算一次）；生成结算单选人民币，应付默认 249,603.94；审批通过后账单变「待支付」，09 确认收款后变「已结算」。

2.1.3 业务规则

  • R-06-001 账单按「客户 × UTC0 自然月」一张，结算期展示「yyyy-mm-01 至 yyyy-mm-最后一天」。当月从该客户第一天有任一账户消耗数据起就有一张「未出账」账单，金额随消耗实时变化；次月 2 日（UTC0）系统自动出账，账单变「待结算」，出账时刻由技术定；全月没有任何账户消耗数据的客户不生成账单（账单管理.html:3931 §2.4.1，D-06-13）。只出结算期 ≥ 上线月的账单，上线月与 07 计提、08、10、11 共用一个配置（index S-18；S-16 定为只从上线月起），上线月之前的结算期不出账单（D-06-36）。已知限制：客户全月零消耗、只有苹果订单或 08 入账时同样不生成账单，渠道金额在 08 / 10 查看（§2.1.5、index §2.9，D-06-45）
  • R-06-002 第二层每个账户一行；同时满足以下条件的账户不展示：消耗、服务费、税费、服务费税费、客户返点、上期预付欠费都为 0，渠道统计金额为 0 或「-」，且没有订单行（D-06-33）；客户返点不为 0 的账户照常展示，应收为负也展示（R-06-011）；05 费用明细 tab、结算单弹窗明细、审批快照用同一口径
  • R-06-003 账单币种 = 该客户账户的消耗币种（同一客户下所有账户相同，D-05-11）；账单里所有金额都用账单币种，千分位、2 位小数、后缀币种代码，格式同 R-05-033；前端只展示服务端返回的 2 位金额，不做二次舍入（D-00-13）；结算币种换算只发生在结算单（R-06-043）
  • R-06-004 一个结算期只有一种计费模式：该结算期的计费模式 = 该结算期第一天（UTC0）客户生效的计费模式；04 的计费模式变更从确定时刻的次月 1 日（UTC0）起生效（预付改后付以审批通过时刻、后付改预付以保存时刻为准，D-00-73、R-04-023、R-04-024），结算期中途不切换（R-04-066），账单内不再按天区分预付日子、后付日子（D-06-12、D-06-24）

  • R-06-005 消耗金额 = 该账户本结算期内每个 UTC0 自然日的消耗之和，消耗数据来源沿用现有；历史消耗被修正时按 R-06-019 / R-06-020 决定账单变不变
  • R-06-006 账户行三项费用：流转计费模式为预付款的账单按 R-06-007 算，后付款的按 R-06-008 算；第一层各金额 = 本账单全部账户行（含当前用户看不到的）之和，渠道统计金额例外（R-06-016）；舍入点按 D-06-19（D-00-13）：中间值可以存更高精度，但不能拿高精度值直接加总代替舍入点
  • R-06-007 预付款账单：按 05 的先进先出（R-05-006），本结算期消耗从哪些分桶扣、各扣了多少 P，就用该分桶的费率快照（R-05-005）算：服务费 = P × 服务费率，税费 = P × 税率，服务费税费 = P × 服务费率 × 税率（快照为客户承担时；公司承担为 0）；锁定中的分桶（审批中的退款、余额分配、余额抵扣占住的，R-05-007）不参与覆盖；返点余额等 0 费率分桶覆盖的消耗服务费、税费按 0，覆盖欠费时同样按 0（D-05-21）；超出全部可用分桶的欠费消耗（R-05-009）先按该日 03 规则用 R-06-008 的算法暂算（阶梯落档时用该段全部消耗落档取比例，按日统计时用当天全部消耗，比例只乘欠费部分；欠费部分的各项各自四舍五入到 2 位，D-06-39），之后有新分桶按先进先出覆盖它时，改按新分桶的快照重算（账单待结算、未锁定、欠费未转入后付账单时生效，R-06-019，D-06-03、D-06-20）；每个分桶的扣减段各自四舍五入到 2 位再相加（D-06-19）
  • R-06-008 后付款账单：逐日取 03 的适用规则（R-03-003；已出账月份重算时以该月出账时刻为 t，R-06-019）与服务费时间区间行（R-03-005、R-03-006；消耗首日首次确定后冻结，早于首日的日子落第 1 行，D-00-56）；把适用条款相同（服务费规则与税率完全相同，D-00-55）且落在同一行时间区间里的连续日子归成一段：固定比例 → 服务费 = 段内消耗 × 比例；阶梯 + 按月统计 → 段内消耗加总后按 R-03-009 落档 × 档位比例（落档用未舍入的原始消耗合计，D-00-13）；阶梯 + 按日统计 → 每天单独落档 × 比例（R-03-010）；税费 = 消耗 × 该段税率；服务费税费 = 服务费 × 税率（客户承担，R-03-028），公司承担为 0；按段（按日统计时按天）各项四舍五入到 2 位后相加（D-06-19）
  • R-06-009 没有适用规则的日子（账户没有任何规则配置，或早于第一条规则起始日期）服务费率、税率按 0：服务费、税费、服务费税费为 0，照常出账、照常结算，不标异常、页面不加提示（D-00-57、D-06-08）；按 0 计的日期范围记在账户行的「无适用规则的日子」里供技术排查与 S-1 导入核对，页面不展示
  • R-06-010 客户返点（后付款账单）= 以下两项之和，按账户加到对应账户行：①07 里「纳入扣减月份」选了本结算期、审批已通过、合计 > 0 的客户返点（R-07-036、R-07-037）；②挂到本账单的结转额（R-06-078）；两项在账户行上分开记录（结转额不是本月新增的返点成本，10 不重复计），账户行应收因此可为负（D-07-16）。「返点时间范围」= ①所属的消耗日期段每段一行「yyyy-mm-dd 至 yyyy-mm-dd」，②每笔一行「yyyy-mm 结转」（yyyy-mm 为来源账单结算期）；都没有显示「-」。预付款的返点在 07 审批通过时直接充进余额（D-00-19），流转计费模式为预付款的账单「客户返点」「返点时间范围」都显示「-」（D-06-11、D-00-18）
  • R-06-011 账户行 应收金额 = 消耗金额 + 服务费 + 税费 + 服务费税费 − 客户返点；第一层「总计」= 各账户行应收金额之和（不去重，D-06-02）；账户行应收、总计、可结算应收都可能为负（返点按账户加，D-07-16；审批期间账单变小，D-00-67），生成结算单时可结算应收为负的按 R-06-077 结转

2.6.3 业务规则

  • R-06-040 「生成结算单」按钮：没有「账单管理（查看）」或「生成结算单」权限点（D-13-01）、流转计费模式为预付款、或状态不是待结算时不显示；其余情况显示，下列任一条件成立时置灰并悬浮显示原因，同时有多条时只显示优先级最高的一条：①「该账单已有审批中的结算单 {审批单号}」；②「有审批中的返点抵扣单 {审批单号}，审批结束后可生成」（07 选了本结算期扣减、合计 > 0、仍在审批中的客户返点单，D-06-23、R-07-053）；③「另有 N 个账户无查看权限，不能生成」（D-06-15）；单号可点，新页打开审批详情（D-06-32）
  • R-06-041 生成结算单弹窗：标题「生成结算单」，右上角 ✕ 关闭，底部只有「提交审批」；只读信息 公司名称、结算期、预估应收金额（= 账单可结算应收，R-06-013）、消耗金额、税费、服务费、服务费税费、返点抵扣（= 账单客户返点合计，R-06-010）、上期预付欠费（有时）、余额抵扣（有时，R-06-076）（账单币种；两种抵扣行名称固定为「返点抵扣」「余额抵扣」）；可结算应收为负时显示结转提示（R-06-077）；下方带本账单第一、二层只读明细（同 R-06-027、R-06-028，有余额抵扣时账户行多一列「余额抵扣」，不带勾选框）
  • R-06-042 结算币种（原型字段名「结算货币」，统一叫结算币种，D-00-68）：必选，下拉单选 人民币 / USD / USDT，默认客户的币种，客户币种为空时没有默认值（R-04-011）；原型占位里的「美元」不做（D-00-08）
  • R-06-043 结算币种与账单币种相同时汇率为 1、不显示汇率；不同时显示「汇率：1 {账单币种} = x {结算币种}（yyyy-mm-dd）」，x = 当天（UTC0）日汇率四舍五入到 4 位，显示与计算都用这 4 位；日期 = 实际取到的那天（当天没有、向前取最近一天时显示那一天）（D-00-74、D-00-62）；提交时服务端按提交当天重新取并锁定，与弹窗不同时按 R-06-048 ② 请用户确认；汇率与汇率日期随单进快照；取不到任何汇率时不能提交，提示「未取到 {账单币种}→{结算币种} 汇率，请稍后再试」
  • R-06-044 应付金额（结算币种）：必填，默认 = （预估应收金额 − 余额抵扣）× 汇率，四舍五入到 2 位；可以改，不设上限；输入按 D-00-82：输入框只接受数字和一个小数点：负号、字母输不进去，小数第 3 位按不下去；粘贴或自动填充的非法内容不写入、保留原值，并就地标红「请输入不小于 0、最多 2 位小数的金额」；任何情况下都不静默四舍五入或截断；输入框下显示「默认 {默认应付} {结算币种}」，应付 ≠ 默认时再显示「已调整 {应付 − 默认}」（带正负号）；切换结算币种时按新汇率重新带出默认值、覆盖已改的值（D-06-09、D-06-21）；预估应收金额为负时按 R-06-077 固定 0.00、只读
  • R-06-045 付款主体：必选，下拉单选，选项 = 该客户当前生效的付款主体；「+ 新增付款主体」、客户没有付款主体、有审批中的付款主体变更、新增提交后的提示与「需审批通过后可选」灰字，做法全部同 05 R-05-042（调起 04 付款主体弹窗、走付款主体变更审批、通过前不在选项里、仅「客户管理-读写」可见）（D-06-21）
  • R-06-046 备注：多行，长度上限沿用现有备注输入框；应付金额 ≠ 默认应付时必填，未填提示「修改了应付金额，请在备注中说明原因」，其余情况选填；即审批发起备注，同时在审批内容区展示（同 D-05-31 做法，D-06-09）
  • R-06-047 点「提交审批」校验结算币种、应付金额、付款主体、备注（R-06-046），不通过在对应位置提示；通过后二次确认，标题「提示」（同 R-05-078），文案「生成结算单需进行审批，是否提交审批单？」（取消 / 确定）
  • R-06-048 确定后服务端复核：「账单管理（查看）」与「生成结算单」权限点、R-06-040 的全部条件、所选付款主体仍在客户当前生效的付款主体里、汇率、账单金额与余额抵扣与弹窗展示一致。①账单或余额抵扣在弹窗打开期间变了：不建单、弹窗不关，按最新数据就地重载：保留结算币种、付款主体、备注；值没变的行原样保留，值变了的行标黄「系统计算值已由 X 变为 Y」；应付金额用户没改过的跟随新默认值，改过的保留用户填的值；顶部提示「数据已更新，请核对后重新提交」，用户再点一次提交才建单；②提交当天汇率与弹窗不同：不建单，返回新汇率，弹确认「汇率已更新为 1 {账单币种} = x {结算币种}（yyyy-mm-dd），换算后金额 {Y}，是否按新汇率提交？」，Y = 按新汇率算的默认应付；用户改过应付的保留其值，确认框里同时列出新的默认值；点确定后按新汇率建单（D-06-30）；③付款主体已不在选项里：提示「付款主体已变更，请重新选择」；④已有在途结算单（句式按 R-12-047）：审批中的用提示框（「知道了」）「该账单已有审批中的生成结算单（审批单号 {单号}，申请人 {姓名}），请等审批结束或撤回后再操作」，已通过、收款单未完成的「该账单已有处理中的结算单（收款单 {财务ID}，待完成），待收款完成后再操作」；单号可点、新页打开审批详情，无查看权限按 R-12-043；⑤R-06-040 ②③ 任一在复核时成立（弹窗打开期间出现审批中的返点抵扣单、可见账户变化）：不建单，提示框显示对应的置灰原因原文，单号可点（D-06-44）；同一弹窗连续点击只提交一次，请求中按钮显示加载
  • R-06-049 复核通过后提交「账单管理—生成结算单」审批（R-12-001、R-12-014）：操作对象客户 = 本客户；涉及账户 = 本账单第二层全部账户（D-00-76）；业务单据 = 弹窗全部内容 + 汇率与汇率日期 + 默认应付金额 + 余额抵扣明细（每个账户取用的分桶与金额，R-06-076）+ 结转额（有时，R-06-077）+ 账单第一、二层全部金额快照（含当前用户看不到的账户行）；发起备注 = 备注。成功后按 12 R-12-018 给弱提示（审批中「已提交审批」；免审直接通过「提交成功，无需审批，已生效」）、关闭弹窗、账单按 R-06-020 锁定、余额抵扣的分桶锁定（R-06-076）
  • R-06-076 余额抵扣（后付）：生成结算单时客户当前生效的计费模式为后付款、且账单可结算应收 > 0 时，系统按账户自动带出「余额抵扣」，只读：每个账户 = min(该账户行可结算应收（< 0 按 0）, 该账户未锁定分桶按退款口径 R-05-027 折算的应退金额)；按先进先出取分桶，分桶余额与应退金额之间的换算同 R-05-027；余额抵扣金额以剩余应收为准，最后一个分桶只取够抵的部分，取用本金与尾差按 R-05-118 ①（本金 = round2(所需金额 ÷ 倍率)，不超过该桶剩余；尾差计入服务费，同 R-05-022，D-06-46）；余额抵扣之和不超过账单可结算应收，超出时从余额抵扣最大的账户行减回（相同按账户名称升序取第一个）（D-06-35）；返点抵扣（= 客户返点，R-06-010）先扣，余额抵扣在其后；提交成功时锁定所取分桶（同退款，R-05-007），驳回、撤回、作废时释放；审批通过时扣减这些分桶，并按 05 写一条「余额抵扣账单」交易明细（取值以 R-05-095、R-05-097 为准：充值金额 = −扣减的分桶金额之和，应付、实收、手续费显示「-」，关联账单 = 被抵扣的本账单）；余额抵扣算客户已付款（计入到款），与返点抵扣（不计到款）分开记录；抵不完的余额留在分桶里供下一张后付账单；客户改回预付后剩余分桶恢复先进先出（D-00-73、D-06-27）
  • R-06-077 可结算应收为负：生成结算单时账单可结算应收 < 0 → 应付金额固定 0.00、只读，不做余额抵扣，不要求备注；结转额 = −可结算应收（账单币种）；弹窗与审批内容区显示「本次抵扣 {返点抵扣 − 结转额}，剩余 {结转额} 结转至下期」；结转额在审批通过时生成（R-06-078），驳回、撤回、作废不生成；只有这一种情况能产生结转，人工把正数应付改成 0 不产生结转（D-00-81、D-06-28）
  • R-06-079 待结算返点提示：打开生成结算单弹窗时，该客户在 07 还有状态为「待结算」的客户返点计提项的，顶部黄条提示「该客户还有待结算的客户返点 {合计} {币种}（{结算期，多个用「、」分隔}），生成结算单后不能再抵扣本账单，可在返点管理里抵扣其他账单或现金打款」，合计取 07 计提项金额（R-07-011）；只提示、不拦提交（D-06-34）
