### 4.1 代定清单（已落 spec D-07-12～23；下面是提交给用户时的原文，留档）

1. 状态（客户返点状态、客情费用状态同一套）：未出账 → 待结算 / 无返点（无客情）→ 审批中 → 待打款（仅现金）→ 已结算；驳回 / 撤回回待结算并按最新数据重算；未提交的行随消耗修正实时变（含 0 ↔ 非 0）。
2. 计算：按 R-03-003 把当月切段；返点每段基数 = 段内（第 1～90 天）消耗 − 段内 MAX 消耗（≥ 0），按月统计 = 段合计落档、按日统计 = 每天落档；客情不扣 MAX、按段合计落档；每段（按日时每天）四舍五入 2 位后加总；无规则日子比例 0。
3. 列口径：消耗金额 = 全月；MAX消耗 = 返点时间范围内；返点 / 客情时间范围 = 当月落在计提天数内的第一天至最后一天；列表里已进单的行显示单内实际金额，其余显示系统计算值。
4. 客户行：累计 = 已结算行实际金额之和；待结算 = 状态待结算的行系统金额之和（审批中、待打款不算）。
5. 弹窗：列出该客户全部待结算、当前用户有查看权限的账户 × 月，默认不勾；勾结算期 = 勾其下全部账户；每行显示系统计算值（只读）+ 实际金额（可改，≥ 0、2 位小数）；至少勾 1 行、合计 > 0 才能提交。
6. 兑现方式按提交时客户当前计费模式：预付 → 余额抵扣 = 各账户实际金额各进一个分桶（R-05-004 ③）；后付 → 余额抵扣 = 选一张可扣减账单（R-06-024），按账户加到该账单对应账户行；现金打款 → 09 付款单。
7. 后付余额抵扣不写交易明细（不动钱不动余额，账单「客户返点」列与结算单支付已体现）；预付抵扣写「客户返点」已完成；现金写「客户返点 / 客情费用」待完成，应付金额记负数。
8. 纳入扣减月份可选任一符合 R-06-024 的账单，不要求晚于返点所属月；账户行应收可以因此为负，只校验整单合计 ≤ 可结算应收。
9. 审批最后一步通过时复核 R-06-024，不满足时不让通过、提示请驳回 —— 需要 12 支持「业务方否决通过」，上报 X。
10. 结算货币 人民币 / USD / USDT，默认客户币种；汇率取提交当天系统日均汇率（缺当天向前取），提交锁定；取不到不能提交。付款主体同 R-05-042。
11. 提交复核：所选行仍是待结算、系统金额与弹窗一致，否则提示「返点金额已变化，请关闭弹窗重新打开」；防连点。
12. 页面：标题「返点管理」，tab「返点信息 / 已提交审批」；搜索公司名称 / 客户别名；筛选 所属账户系统（现有列表）、计费模式；导出不做；客户按待结算客户返点金额降序；分页 10/50/100/300。
13. 权限：页面访问沿用现有菜单权限；数据跟账户查看权限；新增权限点「返点结算」「客情结算」控制两个按钮与提交。
14. 已提交审批：只看自己提交的；列 审批单号、操作对象（客户返点 / 客情费用）、操作客户、所属账户系统、申请人、申请时间、审批状态、操作（同 R-05-089）。
