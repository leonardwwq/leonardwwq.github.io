1 整体概述

1.1 背景与目标

现状：上游渠道（账户系统）每月给一份结算单，格式各不相同；自接苹果的账户系统系统里有苹果订单，其他渠道只能靠人看表格核对，渠道统计金额进不了系统，06 账单的消耗差额、10 的毛利与「算没算完」都缺这一项。

目标：

  • 每个账户系统每个月一行，能看到每个账户的渠道统计金额：自接苹果自动从订单汇总，其他渠道按标准模板上传，整批审批后入账。
  • 上传前就告诉用户哪几行会出错；审批通过后整批替换同账户系统同结算期的旧数据，旧版本留档可追溯。
  • 按账户系统 × 结算期发起渠道付款，审批通过交给 09 付款，付款完成即「已完成」，10 据此判断渠道付完。

可证伪的判定：公共前置（spec.yaml 头部）下，亨利-国内 2026-09 第一层总计 29,746.02 人民币（直接取模板总计，不是反算的 29,746.03）；苹果ASA（自接苹果）第一层 24,000.00 USD（PR-0902 只算一次）；亨利-出海 2026-09 发起渠道付款选人民币，换算后应付 124,850.12 人民币；付款单完成后该行变「已完成」，Kredi Plus 渠道付完、OfferGo 未付完。

2.4 渠道付款

2.4.1 功能描述

结算期结束后，有付款权限的用户对第一层一行（账户系统 × 结算期）发起渠道付款，应付 = 该行总计；可换结算币种；走「渠道对账中心—渠道付款」审批，通过后交给 09 生成付款单。

2.4.3 业务规则

  • R-08-040 「渠道付款」同时满足才显示：有「渠道付款」权限点；结算期已结束（今天 UTC0 ≥ 结算期次月 1 日）；第一层总计不是「-」且 > 0（总计 0.00 的行按 R-08-056 视为已完成；总计 < 0 不能发起，线下处理，D-00-80、D-08-34）；状态待完成；没有在途渠道付款单（审批中，或审批已通过但 09 付款单还不是「已完成」，即待汇出 / 待完成）（D-08-07）。
  • R-08-041 渠道付款弹窗：标题「渠道付款」；只读 结算期、账户系统、小计、税费、渠道返点、总计（本行币种）、应付金额（= 总计，不可改，D-08-07）；本行有共享订单（同一订单号挂在本行多个账户下）时，应付金额下方灰字「本行有 K 个共享订单，在各账户下全额重复列示；应付按订单号去重 = {总计} {币种}」，没有共享订单不显示（D-08-42）；收款主体（选填，R-08-047）；下方带本行第二层只读明细（账户名称、orgid、小计、税费、渠道返点、总计）；原型的「充值金额」不做（D-08-06）。
  • R-08-042 结算币种：必选单选 人民币 / USD / USDT，默认本行币种；与本行币种相同时不显示汇率；不同时显示「汇率：1 {本行币种} = x {结算币种}（yyyy-mm-dd）」与「换算后应付金额：{应付 × 汇率，四舍五入 2 位} {结算币种}」；汇率取当天（UTC0）的日汇率，当天没有向前取最近一天，括号里的日期 = 实际取到的那天；x = 日汇率四舍五入到 4 位，显示与计算都用这 4 位（D-00-74、D-08-37）；提交时按提交当天重取并锁定（D-00-62），与弹窗展示不同时按 R-08-045 ② 确认；汇率与汇率日期随单进快照；取不到任何汇率时不能提交，提示「未取到 {本行币种}→{结算币种} 汇率，请稍后再试」；换算后应付为 0.00 时不能提交，提示「换算后应付金额为 0.00，请改用 {本行币种} 结算」（D-08-47）。

2.5 审批结果处理

2.5.1 功能描述

两种审批结束后，本页怎么处理业务单据（12 只通知结果，R-12-025）。

2.5.2 业务规则

  • R-08-050 两种审批流 0 节点或全部节点被跳过时提交即通过（R-12-018），立即按 R-08-051 / R-08-053 处理；渠道两类审批没有操作对象客户，12 审批配置不给这两类提供「绑定的销售 / 绑定的运营」动态选项（R-12-010，D-08-41），节点只能配指定用户。
  • R-08-051 「渠道对账」审批通过：可入账行按 R-08-034 ③～⑥ 用当时数据再校验一次（①②⑦只看文件本身，结果不变），不通过的跳过、记入入账错误清单（原始行号 + 原因）；其余行按 R-08-021 入账替换并写渠道统计金额、记变化日志（R-08-023）、通知下游（R-08-024）；批次变「已入账」，记录入账行数、跳过行数（D-08-09）；跳过行不算业务执行失败，全部跳过也照常「已入账」（入账 0 行，R-08-057）。审批结果通知申请人沿用 12（R-12-038）。
  • R-08-052 「渠道对账」审批驳回、撤回或作废（作废效果同撤回，R-12-046，D-00-79③）：批次变「已驳回 / 已撤回」，不入账，渠道数据不变；原单不能修改重提（R-12-034），要导入就重新上传。
  • R-08-053 「渠道付款」审批通过（含免审即通过）：生成一张 09 付款单，带 交易类型「渠道付款」、应付金额 = 换算后应付金额（同币种即应付金额；换算后为 0.00 的不能提交，所以 > 0，R-08-042、R-08-045）、币种 = 结算币种、关联审批单号、账户系统、结算期、收款主体（没填为空）、申请人、备注；本行保持待完成，操作列「付款中」；09 确认汇款（付款单 待汇出 → 待完成）不回写本页，本行仍是待完成、「付款中」（R-09-042、R-09-072）。
  • R-08-054 该付款单在 09 变为已完成（确认到账才算完成，D-00-33；回写见 R-09-071）时：本行变「已完成」，记完成时间，已付总计快照 = 该渠道付款单的总计（本行币种）；同时保留该单第二层每个账户的已付快照值（R-08-046 快照里该账户的总计，「-」的账户为空），供 10 详情展示（R-08-091）。
  • R-08-055 「渠道付款」审批驳回、撤回或作废（作废效果同撤回，R-12-046，D-00-79③）：本行保持待完成，「渠道付款」重新出现；原单不能修改重提。
  • R-08-056 第一层总计为 0.00 的行（有值，不是「-」）：结算期结束后、没有在途且没有已完成的渠道付款时视为已完成（无需付款），状态「已完成」、旁边灰字「无需付款」，不显示「渠道付款」，10 判该行账户渠道付完（R-08-091）；之后总计变为不是 0.00、且该行从没有已完成的渠道付款时回到待完成，按 R-08-040 处理（10 按 D-00-66 退回重算）（D-08-44）。第一层总计 < 0 的行不能发起渠道付款，保持待完成、线下处理（已知限制）（D-00-80，D-08-34）。
  • R-08-057 两种审批最后一个审批人通过时，本页不设业务执行失败情形（R-12-045，D-00-79①）：渠道对账通过时再校验不通过的行跳过、其余照常入账（R-08-051）；渠道付款通过时照常生成付款单（R-08-053）；所以通过不会被业务回滚。持「审批配置」权限点的人可作废审批中的两类单，效果同撤回（R-12-046；本页按 R-08-052、R-08-055 处理，D-00-79③）。
