1 整体概述

1.1 背景与目标

现状：账单、返点、渠道、收付款各自在自己页面里，币种也不一样（人民币 / USD / USDT），公司没有地方看每个账户每个月到底赚了多少、这个数算没算准。

目标：

  • 每个账户每个月一行，按 D-00-34 算出毛利润，统一折成人民币。
  • 每行明确告诉大家「算完了没有」，没算完的写清还差哪件事；算完以后数据又变了，自动退回重算并留下记录。
  • 详情里能看到每一项的原币、所用汇率和来源，财务能对着来源页核对；手续费拆成「手续费（09）」「改应付差额」两行，分别对得上 09 和 06。
  • 给 11 提成中心提供按日的毛利（含提成用当日毛利）与服务费。

可证伪的判定：公共前置（spec.yaml 头部）下，橙子-iOS-CN 2026-09 毛利润 32,804.57 人民币（渠道统计金额按共享订单分摊为 17,000.00 USD，手续费 315.83 = 手续费（09）-62.67 + 改应付差额 378.50）；苹果ASA 2026-09 渠道付款单到账后，这一行从「计算中 · 渠道未付完」变「已算完」。

2.1.3 业务规则

  • R-10-001 利润记录按「账户 × UTC0 自然月」一条；结算期 ≥ 上线月，且该账户该月有消耗、或有渠道统计金额、或有手续费（≠ 0）任一项时才有这条记录；当月也有，金额随数据变化。上线月 = 第一个在系统里付渠道款的结算期（index S-18）；06 出账单、07 计提、08 渠道、10 利润、11 提成从同一个上线月起算，共用一个配置，具体月份上线前定（D-10-08、D-10-26）。
  • R-10-002 毛利润 = 消耗 + 服务费 + 税费 − 客情费用 − 客户返点 − 手续费 − 渠道统计金额 − 公司承担服务费税费（D-00-34）。手续费含改应付差额（R-10-007、R-10-009，D-10-02）；服务费税费（06 账户行，客户承担部分）只展示、不进毛利，公司承担服务费税费计入成本（R-10-008，D-10-01）；渠道返点只展示、不再扣（已含在渠道统计金额里，D-00-26）。各项都先折成人民币，再按此计算（R-10-013）。
  • R-10-003 消耗、服务费、税费、服务费税费取 06 该账户该月的账单账户行（R-06-005～R-06-009、R-06-011）。账单锁定或冻结后取快照（R-06-020），之后的消耗修正不影响利润。预付客户同样按消耗出账的金额算，不按充值算。该账户该月在 06 没有账户行时，这四项为 0；其中结算期 ≥ 上线月、该账户该月有消耗却没有 06 账户行的，状态按 R-10-021① 兜底处理为「客户未收完」（D-10-26）。06 账单里的返点抵扣、余额抵扣、上期预付欠费、结转额不是本账户本月的收入，不计入：余额抵扣是客户之前已付的钱，上期预付欠费的消耗已在其所属月份计入（D-00-73、D-00-81）。
  • R-10-004 客户返点、客情费用取 07 该账户该月的计提项（R-07-001）：已进单用实际金额，其余用系统计算金额（R-07-018）。按计提项所属的消耗月份计，不按后付抵扣到哪张账单；没有计提项为 0；后付返点抵扣超出账单产生的结转额（D-00-81）不改变本页客户返点。
  • R-10-005 渠道统计金额、渠道返点取 08 该账户该结算期的总计、渠道返点（R-08-015、R-08-017、R-08-018），共享订单按 R-10-006 拆分。08 为「-」时本页也显示「-」，计算毛利时渠道统计金额按 0，毛利润旁灰字「未含渠道成本」，状态按 R-10-021 停在计算中。例外：系统抓取的账户系统该结算期行已完成后，本期有消耗但没有任何订单的账户视为渠道付完（R-10-021③），渠道统计金额仍显示「-」、按 0 计，不标「未含渠道成本」。系统抓取的渠道返点为「-」。
  • R-10-006 自接苹果（系统抓取）共享订单分摊（D-10-03）：同一结算期同一订单号挂在多个账户下时，订单总计按这些账户本结算期的消耗占比分摊；消耗取 06 该账户该月账户行的消耗金额，账单锁定后取快照，与收入同源（R-10-003，D-10-24）；四舍五入到 2 位，尾差给消耗最大的账户（并列取账户名称升序第一个）；这些账户消耗都为 0 时，整笔给账户名称升序第一个。只挂一个账户的订单整笔归该账户。账户渠道统计金额 = 本账户各订单分到的金额之和，所以各账户相加 = 按订单号去重后的总数；06、08 的展示不变。
  • R-10-007 手续费 = 手续费（09）+ 改应付差额（R-10-009）= 改前应收 − 实收（D-10-02）。手续费（09）取 09 已完成收款单按账户的分摊（R-09-034、R-09-036、R-09-074），原币 = 收款单币种。结算单支付 → 计入对应账单的结算期；账户充值 → 计入收款单完成时间（换算成 UTC0）所在的月（D-10-04）。同一账户月有多张收款单时相加；没完成的收款单不计。付款单汇出 / 到账金额与应付的差额不进毛利（D-10-05、D-09-06）。
  • R-10-008 公司承担服务费税费 = 06 按 R-06-007 / R-06-008 计算服务费税费时、承担方为公司而记为 0 的那部分：后付日子 = 服务费 × 该段规则税率，预付日子 = 分桶扣减金额 × 快照服务费率 × 快照税率；原币按 06 的分段口径各段四舍五入 2 位后相加，按 R-10-012 拆到每天、按 R-10-013 折人民币；客户承担的日子为 0；计入成本（D-10-01）。自接苹果账户系统的「税费」照 R-10-003 计入收入；它是我方要缴的销项税还是代收、要不要同额计入成本，与本条一起待财务确认（Q-10-05），确认前按本条执行。
  • R-10-009 改应付差额 = 生成结算单时系统给出的默认应付（改前应收，已扣返点抵扣、余额抵扣，D-00-73）− 审批通过的应付，应付改大时为负；按该结算单账户行应收占比拆到账户（算法同 R-09-034），原币 = 结算单结算币种。在该结算单变「已结算」时计入对应账单的结算期：有收款单的随收款单完成，落日与汇率同该笔结算单支付手续费（R-10-011）；应付为 0.00、审批通过即已结算的不生成收款单（D-00-80），汇率取审批通过日（UTC0），人工把正数应付改成 0 时差额 = 默认应付全额；可结算应收 < 0、应付固定 0.00 的结转情形（D-00-81）默认应付为 0，不产生改应付差额。

2.2.1 功能描述

2.2.2 业务规则

  • R-10-012 按日拆分（D-10-14）：每项的原币月合计以来源为准（R-10-003～R-10-009）。按来源的逐日金额占比拆到每天（06：当天消耗 × 当天适用费率或分桶快照，已出账月份的费率按出账时刻适用的规则取（R-03-003，D-03-24），公司承担服务费税费同理；07：当天按 R-07-004 / R-07-006 算出的金额），每天四舍五入到 2 位，尾差放在该月最后一个有逐日金额的日子。07 实际金额被人改过的，也按系统逐日金额占比拆。逐日金额全为 0 而月合计不为 0 时，整笔落在该月最后一个有消耗的日子；没有消耗则落在结算期最后一天。

  • R-10-015 某天向前也取不到任何汇率时，用到这天汇率的项人民币为空，页面显示「-」，该行毛利润也显示「-」，状态按 R-10-021④ 为计算中、还差「缺少汇率」；详情里标「未取到 {原币}→人民币 汇率」；汇率补上后自动重算。

2.3 算没算完（定义）

2.3.1 功能描述

每条利润记录自动判断「计算中 / 已算完」；数据变了自动退回重算；已算完的记录变化要留痕（D-00-63～D-00-66）。

2.3.2 业务规则

  • R-10-020 状态只有 计算中 / 已算完，系统自动判断，没有人工确认、退回按钮（D-00-63、D-00-64）；新出现的利润记录为计算中。
  • R-10-021 四件事都完成才「已算完」（D-00-65）：
  • ① 客户收完：该账户在该月账单里有账户行时，账单为「已结算」（含应付 0.00 审批通过即已结算 D-00-80、欠费转入后付账单后随承接账单已结算 D-00-73）；没有账户行时，到了次月 2 日（UTC0）视为完成；兜底：结算期 ≥ 上线月、该账户该月有消耗却没有 06 账户行时，不适用前一句，按「客户未收完」处理，不判已算完（D-10-26）。
  • ② 返点或客情结完：该账户该月客户返点、客情费用计提项都完成（R-07-017）；没有计提项视为完成。
  • ③ 渠道付完：该账户该月有消耗或有渠道统计金额时按 R-08-091：渠道统计金额不是「-」，且所属账户系统该结算期行已完成；付款后才有值或金额变化的账户同样算付完；系统抓取的账户系统行已完成后，本期有消耗、无订单的账户视为付完（R-10-005）；总计为 0.00 的行在结算期结束后视为已完成（D-00-80）。都没有视为完成。
  • ④ 汇率齐全：该月用到的每一天都取得到汇率（R-10-015）。
  • R-10-022 计算中时，状态下方灰字列出还差的，按 ①②③④ 顺序用「、」连接：客户未收完、返点或客情未结完、渠道未付完、缺少汇率。当月（结算期未结束）的「计算中」旁加悬浮提示「金额为实时预估，随消耗数据更新，数据截至 yyyy-mm-dd hh:mm（UTC0）」，截至时间取消耗数据最近一次同步的时间，技术取不到时去掉这半句。
  • R-10-023 任一来源数据变化（06 账单金额或状态、07 计提项金额或状态、08 渠道统计金额变化通知 R-08-024、09 收款单完成、结算单 0 元已结算）时，受影响的利润记录重算金额并重判状态。以下三种完成条件变化同样触发重算，变化记录原因统一记「完成条件变化」（D-10-27）：08 第一层行状态变化（R-08-054、R-08-056，由 08 按 R-08-024 通知）；08 总计为 0.00 的行在结算期结束后视为已完成（R-10-021③）；没有账户行的账户月到次月 2 日（UTC0）视为客户收完（R-10-021①）。汇率补录或修订只触发计算中记录的重算（R-10-010）。已算完的记录在重算期间视为计算中，重算后四件事仍都完成就回到已算完，否则停在计算中（D-00-66）。
  • R-10-024 已算完的利润记录每次因 R-10-023 被重算，且毛利润有变化或状态退回时，记一条变化记录：时间、原因、触发单据、变化前后毛利润、变化前后状态；只追加，不能删改。计算中的记录变化不记。
