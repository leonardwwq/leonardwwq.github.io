## 二、逐条结论（D01～D33）

| 编号 | 结论 | 要点 |
|---|---|---|
| D01 精度 | 部分属实 | 「PRD 一律先舍入再相加」不准：05 退款 R-05-027 先加后舍，与 06 D-06-19 相反。选①「日级仍 4 位」与 D-00-35、R-10-012/013「按日 2 位」冲突 |
| D02 计费模式切换 | 部分属实 | 05 剩余分桶处理确实未定义（R-05-003 与 05「在途单照常走完」矛盾）；04 那处基本已有规则（R-06-004、R-06-003、D-06-10）。选②要连带改 R-06-012（按出账时模式流转），否则上月预付账单会按后付流转 |
| D03 结清模型 | 前半属实 | 「9 月永远结不了」属实；「某天全部 ≥ 0 一起结清」不算问题。后端漏了锁定金额：余额 ≥ 0 但可用余额 < 0 时 PRD 照样判已结算。后端「逐张判是否被分桶覆盖」正好能修掉，只需改 R-06-022 / D-06-07 |
| D04 充值判档 | 反例算反，结论不成立 | 按净额判档，净额 9,000 直接落第 1 档、应收 10,017，唯一解；后端是拿应收比档位（即选②的判法）。按②正算，净额在 [8,984.73, 9,340.56) 无解，「②永远有解」不成立。PRD 已有无解处理（R-05-019/020、D-05-15、G-05-013）。03 / 06 阶梯按消耗（净额）定义，只在充值改按应收会出现两套含义 |
| D05 到账口径 | 属实 | 「09 手动分配只分手续费」PRD 本来如此（R-09-036），要改的是后端现状 |
| D06 后付剩余额度 | 属实 | 选②（含费账单金额）需剔除返点、预付日子、改过的应付 |
| D07 退款复核拒单 | 部分属实 | 只有跨过费率快照不同的分桶时金额才变，「频繁失败」说重了。选②坑：点「全部」照样被拒；余额分配取出侧被改写后「可分配实际金额 = 0」（R-05-059 / D-00-54）不成立 |
| D08 规则跨月 | 部分属实 | 「07、10 会用新规则」不成立：R-07-009 已写出账后通过的规则不作用于该月，10 直接取 06/07 结果。真缺口：06 R-06-019 刷新、10 R-10-012 日拆分没写用哪版规则。选①可能撞同日规则触发 R-03-044 覆盖。D-07-13 仍是「代定」，一起确认 |
| D09 抵扣后为负 | 背景属实，选①有坑 | −750 复算无误。选①死锁：07 已结算不能撤销、收付款不作废，「先处理超额返点」无入口。判断条件应为「可结算应收 < 0」。建议与 D16 合并讨论 |
| D10 多张抵扣单 | 属实 | 无条款覆盖。选②（同时只允许一张）更贴合现有「同对象同时 1 张」写法 |
| D11 抵扣未来月份 | PRD 侧属实；B3 无法核实 | 选②与 D-00-18 冲突；出账前改预付会丢返点。倾向① |

## 四、产品侧真缺口（后端没点破）

1. 后付改预付后，累计消耗从哪天起算（与 Q-06-03 同一缺口）。
2. 结清判断没考虑锁定金额（D03）。
3. 提成规则跨月通过后，11 无退回、无变化记录（D19）。
4. 规则晚于出账的口径，06 R-06-019、10 R-10-012 未写（D08）。
5. 自接苹果账户有消耗但无订单时，永远「渠道未付完」；R-10-006 多币种拆分是否先换算未写。
6. 05 退款（先加后舍）与 06 账单（先舍后加）舍入顺序不一致，可能差 0.01。
7. 额度有效期审批中过期的处理（R-05-064 / R-05-082）。
