## 一、全局口径

### D01 金额精度

- **背景**：PRD 一律 2 位小数、各段先四舍五入再相加（D-00-13、D-06-19、R-07-004）。我们库里与接口都是 4 位，按日保留 4 位再汇总。
- **选项**
  - ① 单据金额（充值快照、结算、计提、收付款）生成时 round2、输入限 2 位；内部日级分摊仍 4 位。与 PRD 验收数据逐分一致。后端中。
  - ② 库里 4 位、对外只显示 2 位。改动小，但和 PRD 验收样例可能差几分钱。
- **前端补充**：选 ② 时，前端逐行四舍五入展示，充值弹窗和审批详情会出现「各行之和 ≠ 总计」差 0.01。
- **建议**：①。
- **决策**：

### D02 计费模式（预付 ⇄ 后付）能否月中切换

- **背景**：PRD 按天取计费模式，同一月预付日子、后付日子分开算再合进一张账单（R-06-004/012/013）。三页都有没闭环的地方：后付改预付当月，后付那几天的费用两头都不收（06 Q-06-03）；预付改后付后剩余分桶怎么处理没定义（05）；后付客户改计费、币种、账期直接生效，从哪天起按新值出账没写（04）。
- **选项**
  - ① 照 PRD 按天分段：后端大，三处缺口还要产品逐个补规则。
  - ② **变更只从次月 1 日（UTC0）生效**：同一月只有一种计费模式。
- **前端补充**
  - 后付客户改**币种、签约主体**现在也是随时直接生效，会影响 05 充值币种和 06 当月账单币种。建议客户有账户、充值或账单后锁定币种，或同样改为次月生效。
  - 选 ② 后，列表和详情要显示待生效状态，例如「后付款（11-01 起改为预付款）」，需要产品给文案。
  - 后付客户隐藏「退款」按钮（R-05-038）：切到后付后剩余余额退不出来。选 ② 要同时改为「后付客户还有可用余额 > 0 的账户时仍显示退款」。
  - 06 R-06-027「未出账账单显示客户当前计费模式」要改为「该月生效的计费模式」。
  - 07 余额抵扣按客户**当前**计费模式走（R-07-035）：9 月后付、10 月已改预付时，9 月的返点会被充进余额且没有可扣减账单。建议按计提项**所属月**的计费模式走，一张单只能勾同一计费模式的月份，列表筛选也按月份口径。
- **建议**：②；剩余分桶保留、可退款，不再被消耗扣。
- **决策**：

### D34 金额输入非法值与试算交互（新）

- **背景**：G-05-017 要求输入 -1、12.345、abc 时标红提示。前端现在：-1 被夹成 0，**12.345 被悄悄四舍五入成 12.35**，abc 回滚，全程不提示。试算在失焦时触发，试算期间没有「计算中」、仍能点提交（带的是旧数），失败时旧数不清。PRD 没定试算时机，也没定错误是就地标红还是顶部提示。全财务模块的弹窗都用同一个输入组件。
- **选项**
  - 输入：① 照 PRD，自由输入、非法标红、提交时拦；② 输入层直接限制（不能输负号和字母，第 3 位小数按不下去，截断不四舍五入），G-05-017 改为「无法输入」；③ 维持自动纠正。
  - 试算：① 失焦或回车触发，试算中该行显示「计算中」、提交按钮置灰，失败标红「试算失败，请重试」；② 输入防抖 500ms 自动试算；③ 加「计算」按钮。
- **建议**：输入 ②（金额不允许静默四舍五入）；试算 ①；错误统一就地标红。
- **决策**：

### D35 提交复核失败与汇率变化时的交互（新）

- **背景**：06、07、08 都规定提交时复核账单 / 计提项 / 渠道金额，变了就不建单，要求「关闭弹窗重新打开」（R-06-048、R-07-051、R-08-045）。每月 2～5 日苹果补数据、账单频繁刷新，正是生成结算单的高峰，失败不会少见；重开会丢掉已选币种、付款主体、备注、改过的应付，**07 逐行改过的金额会全部丢失**。另外弹窗跨 UTC0 零点或当天汇率刚更新时，提交锁定的汇率与界面显示不同，PRD 只定了「金额变了拒单」。
- **选项**
  - 复核失败：① 照 PRD 关闭重开；② 弹窗内按最新数据重新加载：保留币种、付款主体、备注；没变的行保留勾选和已改金额，变了的行标黄「系统计算值已由 X 变为 Y」并重置为新默认值，确认后再提交；③ 在 ② 基础上，07 用户改过金额的行不因系统值变化而拒单。
  - 汇率变化：① 视同金额变化拒单；② 按服务端锁定的汇率提交，确认框回显最终汇率和换算后金额。
- **建议**：复核失败 ②（③ 牵涉审计口径，请产品权衡）；汇率变化 ②。
- **决策**：

## 二、余额与充值（05）

### D03 预付余额与结清模型

- **背景**：PRD 每天把消耗从分桶里先进先出扣掉，余额可以为负；预付账单的服务费、税费按分桶快照逐笔算；客户**全部账户当前余额 ≥ 0** 时整张账单结清（R-05-001/009、R-06-007/021/022）。我们只在月度结算时按账户、按月份先后整月核销，钱不够一分不扣。
- **PRD 自身问题**：「按当前余额 ≥ 0 结清」会把下月欠费带进上月——9 月已补够、10 月消耗把余额拉负，9 月就永远结不了；反过来某天全部 ≥ 0，所有历史欠账一起结清。
- **选项**
  - ① 照 PRD：真相层改逐日核销，后端大。
  - ② 维持现状：账单上的服务费不是客户真正付的，余额不显示欠费。
  - ③ **批次仍为真相 + 余额视图 + 结清回写**：先进先出模拟未结消耗，得出 PRD 的账户余额 / 可用余额 / 剩余额度；结清时按批次快照把费用逐日回写账单；结清改为客户整单判断，加每日触发与欠费通知。后端中～大。
- **前端补充**
  - 列表只有一列「账户余额」，前端绑的是可用余额（已扣锁定），退款一提交列表余额就掉。请定列表显示账户余额、可用余额还是两者（建议账户余额 + 悬浮「其中锁定 x、可用 y」）；余额分配转入侧的「账户余额」列同理。
  - 「剩余额度」现在会显示负数，PRD 规定预付 ≥ 0。
  - 余额分配取出侧「可用余额 ≤ 0 禁用」是前端照退款推出来的，R-05-056 没写，请确认。
  - 06 预付「待结算」账单没有任何入口，也不显示欠多少。建议状态加副标「欠费 X USD，待充值」。
- **建议**：③，结清条件改成「**逐张账单判断该结算期消耗是否已全部被分桶覆盖**」。
- **决策**：

### D04 充值判档按什么金额（推翻已有裁定）

- **背景**：PRD D-00-51（10-19）按本次到账**净额**判档、从高档往低档反推；我们 F1（10-20 你定）按**应付**（实际到账含费金额）判档，已实现。
- **选项**
  - ① 按净额：边界附近会**无解**（例：0–10,000 收 5%、10,000 起收 1%、税 6%，净额 9,000 两档都不成立），需做「可填范围」提示。
  - ② 按应付：永远有解；「按充值金额计算」模式变成逆问题，可能多解。
- **前端补充**：前端现在的「充值金额计算」是最多猜 3 次去逼近，逼近不成功时和后端快照差 0.01，多解时取哪个也没定义。选 ② 要么删掉这个模式（同时删 R-05-043 和审批内容区的「计算方式」），要么后端出正式的「净额 → 应付」接口、产品规定多解时取应付最小的那个。选 ① 时「可填范围」只有后端算得出来，mock 03 的「应收金额总计 —（有错误行，暂不计算）」PRD 正文里没有，请确认。
- **建议**：②，并删掉「充值金额计算」模式；回写 index D-00-51、05 R-05-019～020、G-05-012/013。
- **决策**：

- **建议**：①；差额超过应收 1% 时 09 确认框加提示防误录。

### D07 退款 / 余额分配「提交时与页面金额不同就拒单」

- **背景**：R-05-026。退款金额取决于当前锁的是哪几个桶，消耗每小时推进，弹窗开几分钟税费服务费就变了，投放中的账户会频繁提交失败。
- **选项**：① 照 PRD 一律比对；② 退款 / 取出只复核「≤ 最新可用余额」，金额以服务端为准并在确认框回显；R-05-026 只用于充值和转入。
