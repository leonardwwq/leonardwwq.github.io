# Spotify 风格站点文案规范（中文）

## 1. 目标

保证全站在视觉统一之外，文案语气也保持统一：简短、清晰、可行动。

适用范围：
- 页面标题与副标题
- 导航与分区标题
- 按钮、链接、空状态、提示文案

---

## 2. 文案语气

- 句子短：优先 8-20 个汉字。
- 动作明确：每条文案都回答“用户下一步做什么”。
- 少修饰词：避免“非常、极致、完美”等营销词。
- 统一口吻：默认用“查看 / 浏览 / 打开 / 下载 / 联系”。

---

## 3. 页面层级模板

### 页面头（page head）
- `meta`：2-6 字分类词，如 `个人档案`、`联系渠道`、`案例库`
- `title`：页面主标题，如 `关于我`、`联系我`、`案例库`
- `sub`：一句解释“此页能获得什么”

示例：
- `meta`：`联系渠道`
- `title`：`联系我`
- `sub`：`欢迎通过邮箱或手机联系；简历（PDF）见下方。`

### 分区头（shelf head）
- `title`：分区名称，2-8 字
- `note`：分区说明，1 句
- `action`：可选动作词，如 `回到顶部`

---

## 4. 动作词字典（统一用词）

### 推荐动作词
- `查看`：查看详情、查看案例
- `浏览`：浏览列表、浏览库
- `打开`：打开外链、打开文件
- `下载`：下载文件
- `联系`：联系作者/团队
- `返回`：返回上级页面

### 统一写法（当前站点采用）
- `简历（PDF）`（不要混写成 `简历 PDF`、`PDF 简历`）
- `案例库 / 思考库 / 关于我 / 联系我`（导航固定词）

### 不建议
- 中英文混写动作词：`View Details`、`Open PDF`
- 同义词混用：同页同时出现 `查看` 与 `查阅`

---

## 5. 按钮与链接文案规则

- 按钮优先“动词 + 对象”，如：`查看案例库`、`打开简历（PDF）`
- 链接可短一些，但要能独立理解，如：`回到顶部`
- 同一分区内，按钮动词尽量一致（都用“查看”或都用“打开”）
- 图标按钮必须有 `aria-label`，文案与可见按钮语义一致（如 `复制链接`）

---

## 6. 状态与提示文案

- 默认态：说明“有什么”
- 空状态：说明“缺什么 + 怎么做”
- 成功态：短反馈，如 `已复制`
- 错误态：说明问题 + 建议下一步

示例（空状态）：
- `原型文件尚未放入站点。请将导出 HTML 放入 public/prototypes/... 后即可预览。`

---

## 7. 新页面落地检查清单

发布前确认：
- [ ] 页面头是否有 `meta + title + sub`
- [ ] 分区是否使用统一标题语法（短标题 + 一句说明）
- [ ] 按钮是否使用统一动作词
- [ ] 是否存在中英文混写动作词
- [ ] `简历（PDF）` 写法是否一致
- [ ] 图标按钮是否有可访问标签

---

## 8. 与设计规范的关系

- 视觉规范：`public/spotify/DESIGN.md`
- 文案规范：`public/spotify/COPY_GUIDE.md`

两者配合使用：先定信息层级与动作文案，再映射到统一视觉组件。
